# GitHub 가져오기 충돌과 출처 보존 설계

## 원인

스킬 ID는 저장소와 무관한 디렉터리 이름에서 만들어진다. 기존 Hermes의 `code-review`와 `mattpocock/skills`의 동명 스킬이 충돌했다. 미리보기는 중앙 레코드만 충돌로 표시하지만 설치는 비중앙 레코드 덮어쓰기를 거부하고, UI는 충돌이 표시된 항목에만 설치 ID 변경을 제공한다.

## 합의한 정책

- 기존 플랫폼 스킬의 파일, DB 레코드, 설치 연결을 보존한다. 비중앙 레코드 덮어쓰기를 허용하지 않는다.
- 중앙/비중앙 충돌을 설치 전에 표시한다. 충돌 항목 기본값은 건너뛰기이며, 사용자가 설치 ID를 변경하면 함께 가져올 수 있다.
- 설치 ID와 저장 폴더만 변경한다. 원본 SKILL.md의 name, 설명, 본문 및 동봉 파일은 바꾸지 않는다.
- 기존 중앙 스킬의 명시적 덮어쓰기 동작은 유지하되, 레코드가 소유하지 않는 폴더나 심볼릭 링크를 파괴하지 않는다.
- 변경한 ID는 중앙/비중앙 전체 레코드, 같은 요청의 대상 ID, 실제 대상 경로에 대해 검증한다. 미리보기 이후에도 설치 직전에 재검증한다.

## 출처와 설치 묶음

- 기존 skill_origins를 재사용해 실제 가져온 대상 경로와 저장소, 원본 하위 경로, ref를 연결한다. 확인한 커밋만 기록하며 확인하지 않은 기준을 검증된 것으로 표시하지 않는다.
- 원본 이름과 설치 ID를 구분하고 카드/상세에서 저장소 출처를 표시한다. 저장소 안의 원본을 열 수 있어야 한다.
- 재스캔 및 앱 재시작 후에도 출처가 남아야 한다. skills.source의 일시적인 github 문자열에만 의존하지 않는다.
- 기존 owner/repo 컬렉션을 저장소별 설치 묶음으로 사용한다. 컬렉션은 사용자 편집 가능한 분류이며 출처의 진실 공급원이 아니다. 컬렉션의 이름 변경/삭제가 출처 참조를 제거하지 않는다.
- 출처를 알 수 없는 기존 플랫폼 스킬은 발견 위치만 표시한다. 제작자나 저장소를 추정하지 않는다.

## 사용자 경험

- 충돌 항목에 기존 파일 위치, 가져올 출처, 덮어쓰기를 막는 이유, 건너뛰기/설치 ID 변경 행동을 함께 표시한다.
- 비중앙 충돌에는 덮어쓰기 선택지를 제공하지 않는다. 설치 ID 변경이 원본 SKILL.md 이름을 바꾸지 않음을 안내한다.
- 잘못된 ID/대상 중복은 해당 선택을 유지한 채 수정하도록 한다. 설치 오류 후에도 입력과 선택이 사라지지 않는다.
- 설치됨, 건너뜀, 쓰기 전 차단, 실행 중 실패를 구분한다. 일부 완료를 전체 성공이나 전체 무변경으로 표현하지 않는다.
- 오류에는 실패 대상과 원인 및 다음 행동을 표시한다. 원시 영어 오류 토스트만으로 끝내지 않는다.
- 기존 i18n 언어(한국어, 영어, 중국어)와 카드/상세 UI를 재사용한다.

## 비목표

외부 도구의 실제 플러그인 생성/설치, 새 플러그인 모델, 원본 내용 자동 수정, 자동 업데이트, 묶음 전체 동시 업데이트/제거, 기존 사용자 DB의 수동 정리/마이그레이션은 포함하지 않는다.

## 검증 기준

1. 비중앙 동명 스킬이 미리보기에서 충돌로 표시되고 기본 건너뛰기로 처리된다.
2. 비중앙 덮어쓰기와 다른 비중앙 ID로의 이름 변경은 쓰기 전에 차단된다.
3. 고유 ID로 가져오면 원본 SKILL.md 바이트와 기존 플랫폼 파일/DB/설치 연결이 보존된다.
4. 요청 내부 중복 대상, DB에 없는 기존 폴더, 심볼릭 링크 경로가 안전하게 거부된다.
5. 가져온 출처가 올바른 저장소 하위 경로/대상에 연결되고 재스캔 및 컬렉션 삭제 후에도 유지된다.
6. 중앙 충돌 덮어쓰기와 기존 건너뛰기 동작을 유지한다.
7. 실패 시 결과가 실제 완료/미완료 상태와 일치하고 화면에서 이유와 해결 행동을 확인할 수 있다.
8. 집중 Rust/Vitest 회귀 검증, TypeScript 검사, 브라우저에서 충돌/이름 변경/출처/결과 화면을 확인한다. 사용자 DB를 설치 테스트에 사용하지 않는다.

## 구현 결과와 실패 복구 경계

- `github_import.rs`는 미리보기와 설치의 충돌 분류를 통일하고, 모든 선택 항목을 파일 쓰기 전에 검사한다. 비중앙 레코드와 소유권이 확인되지 않은 실제 경로는 덮어쓰지 않는다.
- 각 스킬은 임시 디렉터리에서 준비한 뒤 대상과 교체한다. 현재 스킬의 저장 실패 시 이전 대상을 복구하며, 복구 자체가 실패하면 남아 있는 백업 경로를 오류에 포함한다. 전체 묶음을 하나의 원자적 트랜잭션으로 취급하지 않으며, 앞서 성공한 항목은 유지하고 결과에 명시한다.
- 스킬 레코드와 출처는 같은 DB 트랜잭션에 저장한다. 확인 가능한 커밋은 다운로드 기준으로 고정하고, 확인하지 못하면 기준 상태를 unknown으로 남긴다. 실제 설치 파일의 manifest를 사용하며 출처를 다시 얻기 위한 별도 다운로드는 하지 않는다.
- 출처는 실제 대상 경로에 연결되며 목록에서는 묶음 조회한다. SQLite 바인딩 제한을 피하도록 500개 단위로 나누어 조회한다.
- 카드와 상세는 원본 이름, 로컬 설치 ID, 저장소 및 원본 SKILL.md 링크를 구분한다. 저장소별 묶음에는 기존 컬렉션을 사용한다.
- 부분 실패 화면은 가져옴/건너뜀/실패/미시도 개수를 구분한다. 재시도 시 이미 성공한 항목을 제외하도록 안내하며, 중복 방지나 전체 완료를 보장한다고 표현하지 않는다. 컬렉션 생성 및 화면 새로고침 실패는 파일 가져오기 실패와 분리한다.
- 설치 ID 편집 시 입력란에 포커스를 주고 기존 값을 선택하도록 React 18 호환 ref 전달을 복구했다.

## 완료 검증

- Rust 집중 회귀: `github_import::tests` 34개, `skill_origin::tests` 9개, `skills::tests` 50개 — 총 93개 통과. 격리된 파일/DB fixture로 충돌 차단, 원본 보존, 실패 복구, 출처 유지 및 조회 경계를 검증했다.
- `cargo clippy --lib -- -D warnings` 통과. 큰 구조화 오류 payload만 Box로 감싸 반환 타입 크기를 줄였으며, 변경 후 importer 회귀 34개를 다시 통과했다.
- 프런트엔드 집중 회귀: 관련 11개 Vitest 파일, 총 221개 통과. 설치 ID 입력 포커스 회귀는 수정 전 실패와 수정 후 통과를 확인했다.
- `pnpm typecheck` 및 변경한 UI/스토어/타입/공통 helper의 집중 ESLint 검사 통과. React 상태 갱신의 `act(...)` 경고는 일부 테스트 출력에 남아 있다.
- Chrome 실제 UI에서 비중앙 충돌의 기본 건너뛰기와 보존 안내, 설치 ID 변경/자동 포커스, 새 설치와 이름 변경의 구분, 저장소 컬렉션 생성, 출처 카드/상세 링크, 부분 실패 후 복구 안내를 확인했다. 브라우저의 IPC/스토어 응답은 격리된 메모리 fixture이며 실제 사용자 설치를 실행하지 않았다.
- `pnpm build`의 TypeScript 컴파일과 Vite production 번들 생성 통과. gray-matter의 eval 사용, 정적/동적 import 혼용, 500 kB 초과 번들 경고는 남아 있으며 빌드를 막지 않았다.
- 사용자 추가 선택에 따라 `pnpm tauri build --debug --bundles app` 통과. 로컬 실행용 산출물은 `src-tauri/target/debug/bundle/macos/skills-manage.app`이다. 생성된 앱에만 ad-hoc 서명을 적용했으며 `codesign --verify --deep --strict --verbose=2` 검증을 통과했다.
- 사용자 DB, 기존 스킬 파일, 설치된 앱은 변경하지 않았다. 생성한 앱을 실행하거나 기존 설치 앱을 교체하지 않았으며, release/DMG/공증 배포는 수행하지 않았다.

## PR CI 전환

- 공개 저장소가 비공개 재사용 워크플로우를 참조하던 구성을 제거하고 `.github/workflows/ci.yml`에 검사를 직접 정의했다. 공유 저장소의 공개 범위나 원격 설정은 바꾸지 않았다.
- PR 생성/업데이트, main/master 푸시 및 수동 실행을 지원한다. 프런트엔드는 frozen 의존성 설치 후 `pnpm build`, `pnpm test`, `pnpm lint`; 백엔드는 macOS에서 `cargo test --lib`, `cargo clippy --lib -- -D warnings`를 실행한다. 테스트/린트 실패를 무시하지 않는다.
- Graphify는 독립 job에서 기존 code-only 산출물과 PR 영역 중첩 검사를 유지한다. 읽기 권한만 사용하고 결과는 PR 댓글 대신 job summary에 기록한다. 그래프 추출/업로드는 기존처럼 보조 검사이며, 실행된 중첩 검사에서 충돌이 발견되거나 명령이 실패하면 해당 job은 실패한다.
- actionlint 1.7.12 검사와 모든 shell 블록의 구문 검사를 통과했다. 격리된 명령 응답으로 PR 하나일 때 비교 생략, 두 PR의 비중첩 통과, 중첩 실패, 검사 도구 오류 코드 전달을 확인했다. GitHub 호스팅 러너에서의 실행은 아직 하지 않았다.
- 저장소 지침에 기록된 기존 프런트엔드 테스트 실패는 제외하거나 숨기지 않았다. 전체 CI가 시작되는 것과 모든 검사가 통과하는 것은 별개다. 현재 브랜치는 자동 PR 생성 패턴 밖이므로 커밋/푸시 뒤 PR 생성이 필요하다.
