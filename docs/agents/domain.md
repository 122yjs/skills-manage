# 도메인 문서

엔지니어링 스킬이 코드를 탐색할 때 이 저장소의 도메인 문서를 읽는 방법이다.

## 탐색 전에 읽을 것

- 저장소 루트의 **`GLOSSARY.md`**
- **`docs/adr/`**: 작업할 영역과 관련된 결정 기록

이 저장소는 단일 맥락 구성이다. `GLOSSARY-MAP.md`는 없다. 파일이 없으면 **조용히 진행한다**. 없다는 사실을 지적하거나 미리 만들자고 제안하지 않는다. `/domain-modeling` 스킬(`/grill-with-docs`, `/improve-codebase-architecture`에서 쓰임)이 용어나 결정이 실제로 정해질 때 만든다.

## 파일 구조

```
/
├── GLOSSARY.md
├── docs/adr/
│   ├── 0001-platform-skill-control-scope.md
│   └── ...
└── src/, src-tauri/
```

## 용어집의 말을 쓴다

결과물(이슈 제목, 리팩터링 제안, 가설, 테스트 이름)에 도메인 개념이 나오면 `GLOSSARY.md`에 정의된 용어를 쓴다. 용어집이 `_Avoid_`로 피하라고 한 말로 바꿔 쓰지 않는다.

필요한 개념이 용어집에 없다면 신호다. 프로젝트가 쓰지 않는 말을 새로 만들고 있는지(다시 생각한다), 실제로 빈 곳인지(`/domain-modeling`에서 다루도록 적어 둔다) 구분한다.

## ADR과 충돌하면 밝힌다
