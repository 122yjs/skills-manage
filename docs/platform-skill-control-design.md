# 플랫폼별 스킬 사용 제어 설계

## 목표

어떤 플랫폼 화면에서도 스킬 하나를 검색하여 활성화, 비활성화, 해당 플랫폼에서 삭제할 수 있는 일관된 조작을 제공한다. 공용 폴더에서 발견했다는 이유만으로 조작을 숨기지 않는다. 공용 원본과 다른 플랫폼의 설치·사용 상태는 유지한다.

## 확인한 현재 문제

- PlatformView는 사용 상태가 있는 읽기·쓰기 가능 설치에만 usageControl을 전달한다. 공용 관측에는 버튼이 없다.
- 폴더 모드 검색은 일치하는 스킬 대신 상위 폴더를 보여줄 수 있어 개별 조작까지 추가 탐색이 필요하다.
- usage.rs는 설치 이동을 통한 비활성만 관리한다. 공용 폴더를 직접 읽는 플랫폼에서는 전용 링크만 제거해도 공용 스킬을 계속 읽는다.
- 이름이 같은 서로 다른 출처가 존재하므로 플랫폼 ID와 스킬 ID만으로 특정 관측을 변경하면 안 된다.

## 상태와 실제 동작을 분리한다

보관함 원본, 플랫폼 설치, 스캔으로 발견한 출처는 기존 모델을 유지한다. 플랫폼별 예외는 별도로 관리한다.

- 활성: 해당 플랫폼에서 사용하도록 설정됨.
- 비활성: 다시 켤 수 있도록 대상 정보와 원래 플랫폼 설정을 보존함.
- 적용 삭제: 해당 플랫폼의 적용을 제거함. 공용 출처는 물리적으로 삭제하지 않으며, 자동 재발견되어도 다시 활성으로 취급하지 않도록 제외 기록을 보존함. 다시 쓰려면 명시적으로 적용한다.
- 확인 불가/지원 안 됨: 실제 제어를 확인하지 못함. 이를 비활성 또는 삭제 성공으로 표시하지 않음.

예외 식별자는 agent_id + 안정적인 출처 경로다. 표시 이름이나 스캔 때 생성되는 임시 행 번호를 키로 사용하지 않는다. 같은 이름의 여러 출처가 설정 하나에 묶이는 플랫폼은 변경 범위를 미리 표시하고, 한 출처만 제어 가능한 것처럼 주장하지 않는다.

## 작은 공통 Interface

기존 관리 설치의 이동·복원·삭제는 유지한다. 플랫폼별 제어 Module은 다음 책임을 한곳에 둔다.

1. 현재 대상과 적용 가능한 동작 조회: 출처 키, 현재 상태, 제어 방식, 불가능한 이유, 재시작 필요 여부.
2. 대상 하나에 활성/비활성/적용 삭제 실행: 실제 플랫폼 설정 또는 설치를 변경한 후 다시 읽어 결과 반환.

화면은 플랫폼 이름별 파일 처리 분기를 갖지 않는다. Store가 IPC를 호출하고 백엔드 Adapter가 실제 처리를 결정한다. 스킬 원본을 읽기 전용으로 취급하는 것과 해당 플랫폼의 사용 설정을 변경할 수 있는지는 별개다.

## 실제 제어 방식

- 전용 관리 설치: 기존 usage.rs의 이동·복원·백업 삭제를 재사용한다.
- 공용/호환 출처: 플랫폼이 제공하는 제외 설정을 수정한다. Codex의 skills.config는 그중 한 Adapter이며 전체 설계를 Codex 전용으로 만들지 않는다.
- 공식 문서로 설정을 확인한 다른 플랫폼은 같은 Interface에 Adapter를 추가한다. 예: Claude Code skillOverrides, OpenCode skill 권한. 버전과 설정 우선순위, 이름 단위 또는 경로 단위 범위를 확인해야 한다.
- 특정 플랫폼이 독립 제외를 지원하지 않거나 확인하지 못한 경우 상태와 이유를 표시한다. DB에만 비활성을 기록하는 구현, 공용 SKILL.md 수정, 공용 링크 삭제, 숨김을 실제 비활성으로 표시하는 구현은 금지한다.
- 전체 플랫폼에 성공을 보장하려고 공용 설치를 자동으로 전용 설치들로 변환하지 않는다. 그 변환은 미설치 플랫폼·추가 스캔 경로·외부 플랫폼의 사용까지 바꿀 수 있는 별도 작업이다.

## 저장과 실패 처리

- 기존 설정의 주석과 무관한 값을 보존한다. 설정 형식을 모르면 덮어쓰지 않는다.
- 변경 전 대상과 설정 원본을 검증하고 동시 작업을 직렬화한다. 파일 저장은 원자적으로 처리한다.
- 원래 설정값을 보존하고 다시 활성화할 때 앱이 쓴 값이 아직 남아 있는지 확인한다. 다른 프로그램이 바꿨다면 덮어쓰지 않고 충돌을 반환한다.
- 설정 파일 변경과 DB 기록 저장 중 일부만 성공하면 복구하고 오류를 표시한다.
- 조회는 실제 설정을 읽어 외부 변경을 반영한다. 예외 기록은 재스캔 정리에서 지우지 않는다.
- 모든 검증은 임시 HOME/설정/DB에서 실행한다. 개발 중 사용자의 실제 스킬이나 플랫폼 설정을 바꾸지 않는다.

## 화면

- 검색 중에는 폴더 보기에서도 일치하는 개별 스킬 카드를 바로 보여 준다. 검색을 지우면 원래 폴더 보기를 복원한다.
- 모든 플랫폼에서 동일한 활성/비활성 및 삭제 진입점을 사용한다. 공용 출처에도 제어 능력에 따라 동작 또는 구체적인 제한 이유를 보여 준다.
- 공용 출처의 삭제는 해당 플랫폼 적용만 제거한다는 확인 문구를 사용한다. 비활성과 삭제를 같은 이름이나 같은 최종 상태로 합치지 않는다.
- 상태 변화 후 검색어를 유지하고 재활성화할 수 있게 한다. 적용 삭제된 항목은 설치됨으로 세지 않으며 재적용 경로를 둔다.
- 플랫폼 전체 관리 설치 개수와 공용 출처 예외를 뒤섞지 않는다. 외부에서 계속 제공될 수 있다는 기존 안내도 실제 결과에 맞게 갱신한다.

## 검증 기준

- 폴더 모드 검색 → 개별 스킬 조작까지 바로 접근.
- 공용 A를 플랫폼 X에서 비활성/삭제해도 원본과 플랫폼 Y 설정은 동일.
- 비활성에서 활성 복원과 적용 삭제에서 재적용이 구분됨.
- 같은 이름·다른 경로, 읽기 전용 플러그인, 버전 미지원, 설정 손상·권한 오류를 성공으로 위장하지 않음.
- 재시작/재스캔 후 상태 지속, 외부 설정 변경 충돌 보호, 실패 롤백.
- 기존 전용 설치 및 전체 비활성 복원 의미 유지.

## 구현 범위와 정직한 완료 기준

공통 구조와 검색 UX를 구현하고, 검증된 실제 Adapter를 연결한다. 각 플랫폼의 확인된 제어 가능 여부를 문서로 남긴다. Adapter가 없는 플랫폼은 미완료 지원 범위로 명시한다. 공통 화면이 있다는 이유만으로 모든 플랫폼의 실제 독립 제어가 완료됐다고 보고하지 않는다.

참고: https://learn.chatgpt.com/docs/build-skills (Codex skills.config), https://code.claude.com/docs/en/skills (skillOverrides), https://opencode.ai/docs/skills 및 https://opencode.ai/v2/docs/skills (서로 다른 설정 버전).

## 2026-09-13 구현 결과

기존 활성/비활성 토글과 별도 삭제 확인을 유지한다. 삭제된 공용 적용에는 재적용 동작을 제공한다. 폴더 모드에서도 검색 중에는 일치하는 스킬 카드를 직접 표시한다.

| 출처/플랫폼 | 현재 구현 범위 |
|---|---|
| 기존 관리 설치 | 기존 이동·복원·삭제 동작 재사용 |
| Codex 공용·호환 출처 | skills.config로 경로별 제외, 비활성·삭제 구분은 별도 기록 |
| Claude 비플러그인 출처 | settings.json의 skillOverrides off로 제외, 이름 단위 영향 안내 |
| Claude 플러그인 | 미지원 사유 표시 |
| Cursor 및 나머지 플랫폼의 공용 출처 | 독립 제어 미지원 사유 표시 |
| OpenCode 공용 출처 | 설정 버전 확인과 처리 코드 추가가 남아 있음 |

최종 관련 Rust 테스트 8개를 부모 에이전트가 직접 재실행하여 통과했다. 프런트 관련 80개와 타입 검사는 부모가 앞선 수정 단계에서 직접 통과를 확인했고, 최종 단계에서는 구현 에이전트가 다시 통과를 보고했다. Clippy·lint도 구현 에이전트가 통과를 보고했다. 전체 프런트 검사에는 AppShell mock 관련 2개 실패가 보고되어 전체 통과로 보지 않는다. 실제 앱 수동 검증과 설치본 교체는 아직 수행하지 않았다. 전체 플랫폼의 공용 스킬 독립 제어는 미완료다.


## 공용 설치 단위 제어 — 개발 재개 결과

### 변경 범위

- 개별 플랫폼 제외와 공용 설치의 활성 상태는 별개다. 플랫폼 카드와 공용 화면은 같은 공유 제어 및 영향 확인창을 사용한다. 개별 제외는 보조 메뉴에 남기고 공용 끄기·켜기가 해당 설정을 바꾸지 않는다.
- 공유 식별자는 실제 설치 항목의 정규화된 경로다. 같은 보관함을 가리키더라도 서로 다른 심볼릭 링크·복사본은 별도 설치다. 이름이나 compatibility 분류만으로 확인된 사용처에 포함하지 않는다.
- 확인된 플랫폼 목록은 관측된 범위다. 목록에 없는 도구도 같은 경로를 읽을 수 있다는 안내를 항상 표시한다. 별도 설치는 계속 작동할 수 있다.
- 보관함 원본과 겹치는 항목 및 외부 플러그인 소유 항목은 이동하지 않는다. 공용 경로와 보관함 경로가 같으면 해당 원본은 제한된다. 오류로 영향 범위를 계산할 수 없는 항목도 숨기지 않고 제한된 항목으로 반환한다.

### 변경과 재확인

- 기존 usage 잠금·파일 이동·DB 기록과 복원 처리를 재사용한다. 심볼릭 링크는 링크 항목만 이동하며 보관함 원본은 유지한다.
- 확인 토큰은 현재 설치·비활성 기록·관측·영향 범위에 연결된다. 변경 직전 재계산해서 달라졌으면 변경하지 않고 최신 영향 목록을 반환한다.
- 재스캔 뒤에도 비활성 기록과 관측을 보존하여 카드와 복원 경로를 유지한다. 복원 위치에 다른 파일이 있으면 덮어쓰지 않는다. 파일 이동·DB 쓰기 실패는 이전 상태로 복구하고 복구 실패도 오류에 포함한다.
- Universal 일괄 끄기는 전체 활성 설치, 일괄 켜기는 `paused_by_bulk` 항목만 대상으로 한다. 확인 목록은 전체 대상과 정확히 일치해야 한다. 개별로 꺼 둔 항목은 일괄 켜기에 포함하지 않는다.
- 프론트는 백엔드가 반환한 `shared_install_id` 또는 정확한 `source_path`만 사용한다. 스킬 ID·이름·보관함 경로로 설치 위치를 추측하지 않는다. 메타데이터가 빠진 대상은 일괄 확인을 중단한다. 일반 플랫폼 전체 토글은 공용 설치를 자동 포함하지 않는다.

### UI와 검증 경계

- 확인 목록은 접힌 상태로 시작한다. 현재 플랫폼을 먼저, 나머지를 이름순으로 표시한다. 펼친 목록은 최대 240px로 스크롤하며 확인 버튼은 별도 footer에 유지한다.
- 전역 중복 조작 차단과 관련 사용 상태·플랫폼·공용 화면·개수 갱신을 연결한다. 변경 후 갱신 실패를 완전 성공으로 표시하지 않는다.
- 모델을 강제 지정하지 않고 등록된 `task` 에이전트로 Rust와 프론트의 파일 소유권을 분리했다. 커밋·푸시·설치본 교체는 수행하지 않았다.
- 실제 검증 결과 및 남은 네이티브 GUI 확인 제한은 `shared-skill-control-tasks.md`에 기록한다. 이 기능은 모든 도구의 독립 제외 지원을 추가한 것이 아니다. 앞 절의 미지원 Adapter 범위는 그대로다.
