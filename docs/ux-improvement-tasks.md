# 일반 사용자 UX 개선 작업 계획

- 작성일: 2026-09-13
- 기준: `main`의 `7f3a287` 및 같은 날 설치된 macOS 앱에서 진행한 UX 평가
- 상태: 계획 작성 완료, 구현 미착수
- 대상 사용자: Codex·Claude Code 등 AI 도구를 사용하지만 스킬의 폴더·링크 구조에는 익숙하지 않은 사람
- 목표: 사용자가 스킬을 찾아 원하는 도구에 설치하고, 현재 상태와 변경 범위를 이해하며 관리할 수 있게 한다.

## 1. 평가 근거와 범위

이번 평가는 화면·접근성 정보·현재 코드를 함께 확인한 결과다. 실제 신규 사용자 실험과 설치·삭제·복원 실행 검증은 아직 수행하지 않았다. 설치된 앱과 현재 코드의 빌드 일치 여부도 구현 시작 때 확인한다.

| 관찰 | 근거 수준 | 계획에서의 처리 |
|---|---|---|
| 통합 검색 결과 선택 후 검색창과 흐린 배경이 남음 | 설치 앱에서 관찰. 다른 화면 이동과 Escape 이후에도 잔류 | 개발 앱에서 재현하고 원인을 좁힌 후 수정 |
| 보관함에 저장하는 마켓플레이스 경로가 설치 완료로 안내됨 | 코드 확인 | 저장과 도구 설치의 완료 문구·후속 행동 분리 |
| 설치 창에 기존 설치 선택과 공용 전환 안내가 함께 나타남 | 화면과 코드 확인 | 현재 상태와 이번 변경 대상 분리 |
| Codex의 사이드바·전체·활성·다른 출처 개수가 서로 다름 | 화면 관찰. 집계 오류 여부는 미확인 | 개수 정의와 데이터 흐름부터 확인 |
| 사이드바에 약 60개 도구가 표시됨 | 현재 사용자 설정에서 관찰 | 신규 사용자의 기본값으로 단정하지 않고 기존 선택 보존 |
| 발견 목록에 같은 Resources 이름과 앱·백업 폴더가 섞임 | 화면과 출처 경로 확인 | 출처와 표시 이름 개선 |
| 한국어 화면에 영어 조작 문구와 어려운 용어가 남음 | 화면과 코드 확인 | 제품 문구의 한국어·영어·중국어 정합성 개선 |
| 백업 기록이 길게 펼쳐지고 언어·테마 설정은 아래에 있음 | 화면과 코드 확인 | 기본 설정 우선 배치, 백업 표시량 제한 |
| 작은 설명문과 아이콘에 많은 상태가 집중됨 | 화면과 스타일 코드 확인 | 가독성·키보드·접근성 검증 후 개선 |

설치된 스킬 수와 경로는 관찰 당시의 예시이며 고정된 테스트 기대값으로 사용하지 않는다. 검색창 잔류와 개수 차이의 원인은 아직 확정하지 않았다.

### 유지할 제품 동작

- 도구 **표시/숨김**, 설치 **활성/비활성**, **설치 삭제**, **보관함 원본 삭제**를 구분한다.
- 도구를 숨겨도 스캔·설치·활성 상태는 바뀌지 않는다.
- 공용 설치는 이를 지원하는 도구에서 사용하는 별도 설치 대상이다. 모든 도구에 설치됐다고 표현하지 않는다.
- 공용 경로를 읽을 수 있다는 사실과 실제로 해당 경로에서 발견됐다는 사실을 구분한다.
- 플러그인 등 다른 출처의 스킬은 관리 설치와 구분하고, 개별 도구의 삭제·비활성 조작으로 함께 변경하지 않는다.
- 활성은 설치 파일 상태다. 실행 중인 AI 대화에서 이미 읽은 지시가 즉시 취소된다고 보장하지 않는다.
- 현재 보관함 경로는 설정에서 읽는다. 과거 문서에 있는 `.agents/skills`를 원본 보관함으로 고정하지 않는다.
- 기존 `UnifiedSkillCard`, 상태 저장소, 설치·복구 로직과 테마 체계를 재사용한다.

### 이번 계획에 포함하지 않는 일

- 전면적인 디자인 교체, UI 라이브러리 교체, 모바일 앱 대응
- 인기 도구 추적을 위한 사용 기록 수집, 새로운 추천 서비스, 유료 번역 자동 실행
- 실제 사용자 파일을 사용한 설치·삭제 실험, 실행 중인 DB 자동 복원, 백업 보존 기간 변경
- 요청 없는 커밋·푸시·PR·배포·설치 앱 교체

## 2. 실행 순서

P1은 사용을 막거나 결과를 오해하게 하는 문제, P2는 탐색·학습·관리 부담을 줄이는 작업이다. 크기는 작업을 나누기 위한 상대적인 범위이며 일정 약속이 아니다.

| ID | 우선순위 | 작업 | 선행 작업 | 크기 |
|---|---|---|---|---|
| UX-00 | P1 | 재현 환경과 현재 동작 기준 확보 | 없음 | 작음 |
| UX-01 | P1 | 검색창 닫힘·화면 이동 복구 | UX-00 | 중간, 원인에 따라 조정 |
| UX-02 | P1 | 사용자 용어와 상태 정의 통일 | UX-00 | 작음 |
| UX-03 | P1 | 보관함 추가와 도구 설치 흐름 분리 | UX-01, UX-02 | 중간 |
| UX-04 | P1 | 설치 선택과 변경 범위 명확화 | UX-02, UX-03 | 중간 |
| UX-05 | P1 | 개수·출처·활성 상태 설명 정리 | UX-02 | 중간 |
| UX-06 | P2 | 사이드바와 보관함 조작 단순화 | UX-02, UX-05 | 중간 |
| UX-07 | P2 | 발견된 스킬의 출처 구분 | UX-02, UX-05 | 중간 |
| UX-08 | P2 | 기본 설정과 복구 안내 접근성 개선 | UX-02 | 작음 |
| UX-09 | P2 | 상세 정보·다국어·가독성·접근성 마무리 | UX-03~UX-08 | 중간 |

권장 묶음은 **UX-00~01 → UX-02~05 → UX-06~09 → UX-10**이다. 서로 독립적인 파일 조회는 병렬로 처리하되 공유 컴포넌트 변경은 충돌하지 않게 순서를 잡는다.

## 3. 작업별 체크리스트

### UX-00. 재현 환경과 기준 확보

- [ ] 브랜치·기존 변경·실행 앱 경로·버전·빌드 시점을 기록한다.
- [ ] `node`, `pnpm`, `cargo` 버전과 현재 실행 가능한 검증 명령을 확인한다.
- [ ] 기존 테스트 유틸리티와 임시 DB·디렉터리 방식을 확인해 실제 설치 폴더를 건드리지 않는 검증 환경을 준비한다.
- [ ] 보관함 비어 있음, 기존 설치 있음, 공용·플러그인 중복 출처, 개별 비활성, 다수 백업 상태를 대표 데이터로 정리한다.
- [ ] 최초 실행은 기존 사용자 설정을 초기화하지 않고 별도 환경에서 확인한다.

완료 기준: 이후 작업에서 같은 조건으로 재현할 수 있고, 원래 사용자 데이터와 설정이 보존된다.

### UX-01. 검색창 닫힘과 화면 이동

대상: `GlobalSearchDialog.tsx`, `command.tsx`, `dialog.tsx`, `SkillDetailDrawer.tsx`, 관련 테스트.

- [ ] `⌘K → aside-browser 검색 → Enter` 후 상세 화면과 검색창의 실제 표시 상태를 확인한다.
- [ ] 마우스 결과 선택, Escape, 바깥 클릭, 재열기에서도 같은 현상이 생기는지 확인한다.
- [ ] 논리적인 열림 상태, DOM에 남은 창·배경, 닫힘 애니메이션, 포커스 복귀를 따로 확인해 원인을 좁힌다. 원인을 확인하기 전 애니메이션 전체 제거 등 광범위한 변경은 하지 않는다.
- [ ] 결과 선택 후 검색창과 배경이 제거되고, 상세 화면으로 키보드 초점이 이동하게 한다. 취소하면 검색을 열었던 버튼으로 초점을 돌린다.
- [ ] 공통 대화상자를 수정했다면 설치 창·상세 패널·컬렉션 창도 확인한다.

완료 기준:

- 검색 → 결과 선택 → 상세 보기 → 뒤로 가기를 연속 5회 수행해도 창이나 흐린 배경이 남지 않는다.
- 취소 후 배경을 클릭하거나 Tab으로 이동할 수 있다.
- 컴포넌트 검사뿐 아니라 실제 Tauri 개발 앱에서도 확인한다.

### UX-02. 용어와 상태 정의

대상: `src/i18n/locales/{ko,en,zh}.json`, `recoveryResources.ts`, 관련 설계 문서와 화면.

| 사용자 표현 | 의미 |
|---|---|
| 보관함에 추가 | 원본을 보관함에 저장. AI 도구 설치 완료를 뜻하지 않음 |
| 도구에 설치 | 선택한 도구의 설치 위치에 스킬을 제공 |
| 활성 / 비활성 | 이 앱이 관리하는 설치를 도구가 읽게 하거나 잠시 중단 |
| 이 앱에서 관리 | 활성 변경·설치 삭제 등 관리 작업을 지원하는 설치 |
| 다른 출처에서 제공 | 공용·플러그인 등 현재 위치에서 직접 제어하지 않는 출처 |
| 설치 삭제 | 선택한 설치 위치에서 제거. 보관함 원본 유지 |
| 보관함 원본 삭제 | 원본 제거. 영향을 받는 설치와 복구 범위를 별도로 안내 |

- [ ] ‘이식’은 ‘다른 도구에 설치’, ‘프론트매터’는 ‘스킬 기본 정보’처럼 사용 목적 중심으로 바꾼다.
- [ ] ‘읽기 전용’에는 이 화면에서 수정할 수 없다는 뜻과 관리 가능한 위치를 함께 설명한다.
- [ ] 한국어 화면의 `Recommended`, `Official Directory`, `Search`, `GitHub origin`, `Link origin`, `Close` 등 조작 문구를 번역 키로 전환한다.
- [ ] 외부 스킬의 고유 이름·원문·코드까지 일괄 번역하거나 수정하지 않는다.
- [ ] 뒤 작업에 필요한 완료·부분 실패·재시도 문구를 먼저 정의한다.

완료 기준: 같은 동작에 같은 표현을 사용하며, 세 언어에서 번역 키나 불필요한 영어 조작 문구가 그대로 보이지 않는다.

### UX-03. 보관함 추가에서 도구 설치까지 연결

대상: `MarketplaceView.tsx`, `MarketplaceSkillDetailDrawer.tsx`, `GitHubRepoImportWizard.tsx`, `marketplaceStore.ts`, `centralSkillsStore.ts`.

- [ ] 추천·공식 소스·skills.sh·GitHub 가져오기 각각에서 실제 저장 위치와 후속 작업을 확인한다.
- [ ] 보관함 저장만 수행하는 버튼·배지·완료 알림을 ‘보관함에 추가’ 의미로 통일한다.
- [ ] 추가 성공 후 ‘사용할 도구 선택’과 ‘나중에 설치’를 제공하고 기존 설치 창을 재사용한다.
- [ ] 후속 창을 취소해도 보관함 추가 결과가 유지됨을 명확히 한다.
- [ ] 이미 보관한 스킬은 재추가 대신 보관함 보기·도구 설치로 이어지게 한다. 기존 충돌 검사와 출처 식별을 유지한다.
- [ ] 성공 알림은 실제 완료 범위를, 일부 실패 알림은 성공·실패 대상을 구분한다. 실패한 대상만 다시 시도할 수 있게 한다.

완료 기준: 보관함에만 저장한 상태를 도구 설치 완료로 알리지 않으며, 사용자가 마켓플레이스에서 원하는 도구 설치까지 이어갈 수 있다.

### UX-04. 현재 설치 상태와 이번 변경 분리

대상: `InstallDialog.tsx`, `PlatformInstallDrawer.tsx`, `CollectionInstallDialog.tsx`, `src/lib/agents.ts`, 관련 저장소·테스트.

- [ ] ‘현재 설치된 도구’는 상태 정보로, ‘추가할 도구’는 선택 항목으로 분리한다.
- [ ] 추가 설치 흐름에서 기존 설치를 해제한 것으로 오해할 수 있는 체크박스 구성을 없앤다. 새 대상이 없으면 실행 버튼을 비활성화한다.
- [ ] 공용 설치로 전환하는 작업은 일반 추가와 구분하고 사용자가 명시적으로 선택하게 한다.
- [ ] 실행 전 ‘새로 설치 / 유지 / 공용 설치로 전환하며 정리’ 대상을 요약한다. 이름만 같은 다른 출처는 합치지 않는다.
- [ ] 설치 방식은 기본 ‘자동’을 유지하고, 링크·복사 선택과 기술 설명은 고급 옵션으로 접는다.
- [ ] 단일 설치와 컬렉션 일괄 설치에 맞는 기본 선택을 각각 검증하고, 숨긴 도구도 설치 대상으로 찾을 수 있게 한다.
- [ ] 기존 `AGENTS.md`의 ‘이미 연결된 플랫폼 기본 체크’ 설명은 이 계획에서 제안한 새 동작이 구현되는 단계에 맞춰 갱신한다.

완료 기준:

- 추가 대상 선택 해제만으로 기존 설치가 삭제·비활성화되지 않는다.
- 공용 설치를 명시적으로 선택하지 않은 추가 작업은 기존 개별 설치 구조를 바꾸지 않는다.
- 실행 전 요약과 실제 파일·관리 기록 변경이 일치하며, 충돌·부분 실패 시 원본이 보존된다.

### UX-05. 개수와 상태를 믿고 읽을 수 있게 정리

대상: `Sidebar.tsx`, `PlatformView.tsx`, `UniversalInstallView.tsx`, `UnifiedSkillCard.tsx`, `PlatformInstallDrawer.tsx`, 관련 저장소 및 Rust 조회·집계 코드.

- [ ] 사이드바, 전체 탭, 활성·비활성, 다른 출처 숫자가 무엇을 세는지 표로 정리한다. 스킬 이름 수와 설치 위치 수를 혼용하지 않는다.
- [ ] 동일 시점의 파일 → 스캔 결과 → DB → 화면을 대조한다. 실제 집계 결함과 설명 부족을 구분한다.
- [ ] 같은 개념의 숫자는 같은 집계 기준을 사용하고, 다른 기준의 숫자에는 이름과 짧은 도움말을 붙인다.
- [ ] 공용·플러그인 중복과 관리 설치의 관찰 기록을 확인해 같은 위치를 중복 집계하지 않는다. 다른 위치의 같은 이름은 무조건 합치지 않는다.
- [ ] 상태를 ‘활성 / 비활성 / 설치 안 됨 / 다른 출처에서 제공’으로 구분하고 작은 아이콘의 밝기에만 의존하지 않는다.
- [ ] 재스캔·설치·삭제 후 관련 숫자를 갱신하고, 조회 실패를 0개나 빈 목록으로 위장하지 않는다.
- [ ] 도구 재시작·재로드·새 대화가 필요할 수 있다는 안내를 유지한다.

완료 기준: 사용자에게 각 숫자의 범위를 설명할 수 있고, 같은 기준의 수치가 화면 간 일치한다. 비활성과 미설치, 공용 제공을 구분할 수 있다.

### UX-06. 메뉴와 보관함 조작 단순화

대상: `Sidebar.tsx`, `DashboardShell.tsx`, `DevToolSetupDialog.tsx`, `CentralSkillsView.tsx`, `LibraryFolderNav.tsx`, 관련 테스트.

- [ ] 기존 도구 표시 선택을 보존한다. 최초 실행에서 감지된 도구를 우선 제시하는 현재 동작을 검증한다.
- [ ] 도구 목록의 그룹 접기와 표시 설정 접근성을 개선한다. 실제 사용량 추적이나 새로운 자동 추천은 추가하지 않는다.
- [ ] 사이드바 어디를 보고 있어도 주요 메뉴와 도구 표시 설정을 쉽게 찾게 한다.
- [ ] 보관함에서 검색과 주요 추가 행동을 먼저 보이고, 정렬 기준·방향은 하나의 메뉴로 묶는다.
- [ ] 전역 검색·폴더 검색·현재 목록 검색의 범위를 문구로 구분한다. 보조 폴더 탐색은 접을 수 있게 한다.
- [ ] 스킬을 선택했을 때 일괄 작업을 강조하되, 키보드로 선택 기능을 찾을 수 있게 한다.
- [ ] 상세 보기 후 복귀 시 검색어·필터·스크롤이 유지되는지 확인한다.

완료 기준: 기존 표시 설정과 설치 상태가 유지되며, 기본 창에서 스킬 검색·상세·설치 행동을 쉽게 찾을 수 있다.

### UX-07. 발견 결과의 출처 구분

대상: `DiscoverView.tsx`, 발견 결과 자료형·저장소, 필요 시 Rust 발견 코드.

- [ ] 현재 결과에 포함되는 프로젝트·앱 내부·백업 경로를 확인한다.
- [ ] ‘내 프로젝트 / 설치된 앱에서 제공 / 백업에서 발견’처럼 출처를 표시한다. 경로 근거가 부족하면 임의로 단정하지 않는다.
- [ ] 이름이 같은 `Resources` 등은 앱 이름이나 상위 폴더를 보조 표시하고 전체 경로도 확인할 수 있게 한다.
- [ ] 백업 결과는 별도 필터나 접힌 그룹으로 분리하되, 검색 결과나 디스크 파일을 삭제하지 않는다.
- [ ] 읽기 전용 여부, 보관함에 추가, 도구에 설치의 차이를 항목에서 알 수 있게 한다.

완료 기준: 같은 폴더 이름의 결과를 구분할 수 있고, 사용자가 원래 위치와 제공 주체를 확인한 후 가져올 수 있다.

### UX-08. 설정과 복구 안내 정리

대상: `SettingsView.tsx`, `RecoverySettings.tsx`, `CentralVaultSettings.tsx`, [복구 안내](recovery-guide.md).

- [ ] 언어·테마·도구 표시를 기본 설정으로 먼저 배치하고, 보관함 위치·연결 설정·백업을 별도 구역으로 정리한다.
- [ ] 백업은 최근 5개와 전체 개수, ‘전체 보기’를 제공한다. 전체 목록도 페이지 나누기 등 간단한 방식으로 표시량을 제한한다.
- [ ] DB 백업과 스킬 파일 백업의 복구 범위를 구분한다.
- [ ] 현재 존재하는 `recovery-guide.md` 내용을 재사용해 화면에서 ‘복원 방법 보기’로 접근하게 한다. 파일 경로 링크만 두지 않고 배포 앱에서도 읽을 수 있게 한다.
- [ ] 백업의 자동 만료 정책, 영구 삭제 확인, 복원 충돌 보호를 유지한다.

완료 기준: 백업이 100개인 대표 데이터에서도 기본 설정에 바로 접근하며, 화면에서 파일 복원과 DB 수동 복원의 차이를 확인할 수 있다.

### UX-09. 상세 화면·가독성·접근성 마무리

대상: `SkillDetailView.tsx`, `UnifiedSkillCard.tsx`, `LocalizedSkillDescription.tsx`, 공통 UI·CSS·번역.

- [ ] 상세 화면에서 스킬의 용도·설치 상태·다음 행동을 먼저 보여주고 GitHub 원본 연결·파일 경로·기술 정보는 접힌 보조 영역으로 옮긴다.
- [ ] 설명문은 14px을 우선 검토하고 줄 수·간격을 조정한다. 10px 문구에 핵심 상태를 맡기지 않는다.
- [ ] 설명이 생략됐을 때 전체 내용을 확인할 수 있게 하고, 번역 부가 행동은 주 행동보다 약하게 표시한다.
- [ ] 로컬 번역·API 번역의 기존 동의와 비용 관련 흐름을 유지한다.
- [ ] 반복되는 ‘스킬 선택’ 접근성 이름에 스킬 이름을 포함하고, 검색 필드·아이콘 버튼·상태·오류에 의미 있는 이름과 안내를 제공한다.
- [ ] 키보드 순서, 보이는 포커스, 대화상자 취소·초점 복귀, 탭 조작을 확인한다.
- [ ] 밝은·어두운 테마에서 일반 텍스트 대비 4.5:1을 확인한다. 클릭 영역은 WCAG 2.2의 24 CSS px 또는 간격 예외를 기준으로 보고 주요 조작은 여유 있게 만든다.
- [ ] 최소 창 900×600, 기본 창 1200×800, 큰 창과 200% 확대에서 핵심 정보·버튼이 잘리지 않는지 확인한다.
- [ ] 모션 감소 설정에서 애니메이션을 줄여도 창 닫힘·로딩 완료가 정상 동작하는지 확인한다.

완료 기준: 마우스·키보드로 주요 작업을 수행할 수 있고, 상태를 색에만 의존하지 않는다. 확대와 테마 변경에도 핵심 행동이 유지된다.

## 4. 검증과 종료 조건

검증 명령은 [Tauri 빠른 검증 지침](../.agents/skills/tauri-fast-verify/SKILL.md)을 따른다. 과거 문서의 테스트 성공 수나 기존 실패 목록을 현재 결과로 대신하지 않는다.

### 작업별 개발 검증

- [ ] 프런트엔드 변경: `pnpm typecheck`, `pnpm lint`, 영향을 받은 Vitest 파일을 실행한다.
- [ ] 공유 대화상자 변경: 검색·설치·상세 패널 관련 회귀 검사를 함께 수행한다.
- [ ] Rust 변경: 변경 모듈의 `cargo test`를 실행하고 필요한 컴파일·Clippy 검사를 수행한다.
- [ ] 실제 창·포커스·파일 동작: `pnpm tauri dev`로 확인한다. 브라우저 모의 데이터만 통과한 결과를 실제 앱 검증으로 대신하지 않는다.
- [ ] 테스트는 결과와 데이터 보존을 검증한다. 단순 문구·배치 변경마다 구현을 그대로 복사한 테스트를 늘리지 않는다.
- [ ] 넓은 공통 변경을 통합한 마지막 단계에 전체 관련 테스트를 실행한다. 실패를 발견하면 현재 기준에서도 발생하는지 확인해 구분한다.
- [ ] 릴리스 빌드·DMG·설치본 교체는 별도 요청이 있을 때 진행한다.

### UX-10. 최종 사용 시나리오

아래 설치·삭제·복구 검증은 임시 스킬과 격리된 데이터로 수행한다.

| 시나리오 | 성공 기준 |
|---|---|
| 스킬 검색 후 상세 확인 | 검색창이 완전히 닫히고 상세를 읽고 돌아올 수 있음 |
| 마켓플레이스에서 보관함에만 추가 | 보관함 추가와 도구 설치가 다르다는 사실을 알 수 있음 |
| 보관한 스킬을 Claude Code에 설치 | 대상과 결과가 일치하고 완료한 위치를 안내함 |
| 이미 설치된 스킬을 다른 도구에도 추가 | 기존 설치를 변경하지 않고 선택한 새 대상에만 추가함 |
| 공용 설치로 전환 후 취소 | 변경 요약을 이해할 수 있고 취소하면 파일·기록이 그대로임 |
| 관리 설치 하나 비활성 후 다시 활성 | 원본·수정한 복사본이 보존되고 다른 출처에는 영향이 없음 |
| 설치만 삭제 | 보관함 원본과 다른 도구의 설치는 남음 |
| 같은 이름의 여러 출처 확인 | 각각의 위치·관리 범위를 구분할 수 있음 |
| 백업 다수 상태에서 언어 설정 찾기 | 긴 백업 목록을 지나가지 않고 기본 설정에 접근함 |
| 네트워크 오류·부분 설치 실패 | 성공 범위와 실패 이유가 표시되고 재시도할 수 있음 |

- [ ] 개발 검증 결과를 작업 ID별로 기록한다. 재현 조건, 실행 명령, 결과, 남은 문제를 포함한다.
- [ ] 가능하면 처음 사용하는 사람 3~5명에게 ‘스킬 찾기 → 도구 설치 → 비활성 → 설치만 삭제’를 설명 없이 수행하게 한다. 테스트 참여 요청이나 연락은 별도 사용자 지시가 있을 때 진행한다.
- [ ] 완료 여부·걸린 시간·잘못 누른 동작·도움 요청을 기록하고, 사용자가 결과와 변경 범위를 자기 말로 설명할 수 있는지 확인한다.
- [ ] 출시 전 목표는 검색창 잔류 0건, 의도하지 않은 파일·설치 변경 0건, 핵심 흐름 완료 및 완료 범위 이해다. 소수 참여자의 결과를 전체 사용자 통계처럼 표현하지 않는다.
- [ ] 참여자 검증을 수행하지 못했다면 개발 검증과 분리해 미완료로 남긴다.

작업 체크박스는 구현과 해당 완료 기준 검증이 모두 끝났을 때만 표시한다. 계획 작성 자체는 구현 완료를 뜻하지 않는다.
