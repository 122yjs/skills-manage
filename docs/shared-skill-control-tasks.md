# 공용 스킬 제어 구현 작업

## 담당과 원칙

- 모델 강제 지정 없이 등록된 `task` 에이전트로 Rust·프론트 작업을 분리하고 부모가 통합 검증한다.
- 중단된 `glorious-dodo`의 미커밋 구현을 보존하여 개발을 이어갔다.
- Ponytail full 적용: 기존 설치 이동·복원, Store, UnifiedSkillCard, Dialog를 재사용한다. 새 의존성과 범용 제어 프레임워크는 추가하지 않는다.
- 기존 변경과 사용자 실제 스킬·설정을 보존한다. 커밋·푸시·설치 앱 교체는 범위 밖이다.

## 작업 1 — 공유 설치 판별과 영향 범위

- [x] scanner 관측, 관리 설치, 비활성 설치를 실제 설치 경로와 링크 관계로 연결한다. 이름이나 compatibility 분류만으로 묶지 않는다.
- [x] 같은 원본을 가리키는 독립 링크와 복사본은 별도 설치로 구분한다.
- [x] 기존 플랫폼 제어 응답에 공유 설치 식별자, 공용 상태, 개별 제외 상태, 확인된 플랫폼, 별도 설치, 제한 사유를 최소한으로 추가한다.
- [x] 보관함 원본과 겹치는 설치 및 외부 플러그인 소유 경로는 자동 이동하지 않는다. 제한 사유와 관리 경로를 반환한다.

완료 기준: 같은 이름의 다른 출처를 건드리지 않고, 확인된 영향 범위와 미확인 사용처를 구분한다.

## 작업 2 — 공유 설치 비활성화와 복원

- [x] usage.rs의 기존 잠금·이동·복원 처리를 재사용하는 공유 설치 변경 진입점을 연결한다. 기존 공유 원본 보호 검사를 전역으로 해제하지 않는다.
- [x] 링크는 링크만 이동하고 보관함 원본과 플랫폼별 제외 설정은 유지한다.
- [x] 실행 직전 경로와 영향 범위를 재검증한다. 확인 이후 범위가 달라졌다면 갱신된 확인창으로 돌려보낸다.
- [x] 비활성 기록을 재스캔 후 플랫폼 조회에 포함해 카드와 복원 경로를 유지한다.
- [x] 복원 위치 충돌은 덮어쓰지 않는다. 파일·DB 오류 시 기존 복구 방식을 재사용하고 복구 실패도 알린다.

완료 기준: 공용 끄기와 켜기를 반복해도 기존 플랫폼별 제외 상태가 그대로 남는다.

## 작업 3 — 카드와 영향 확인창

- [x] PlatformView와 UniversalInstallView에서 동일한 공유 제어를 사용한다. 공용 활성/비활성과 개별 제외 상태를 구분한다.
- [x] 카드에는 확인된 플랫폼 수를 표시한다. 플랫폼 목록은 접힌 상태로 시작하고 펼치면 최대 높이 240px의 스크롤 목록을 제공한다.
- [x] 현재 플랫폼을 먼저, 나머지는 이름순으로 표시한다. 활성화와 비활성화 모두 영향 확인을 받는다.
- [x] 확인된 플랫폼 외에도 같은 경로를 읽는 도구가 영향을 받을 수 있음을 안내한다. 별도 설치가 발견되면 계속 사용될 수 있음을 표시한다.
- [x] 지원되는 플랫폼의 개별 제어는 보조 메뉴로 유지한다. 플랫폼 전체 비활성화에 공유 설치를 자동 포함하지 않는다.
- [x] 공용 화면의 기존 일괄 제어에도 영향 확인을 적용한다. 새 일괄 제어 선택 기능은 추가하지 않는다.
- [x] Store에서 중복 조작을 막고 관련 플랫폼·공용 화면·개수를 갱신한다. 모든 새 문구는 기존 i18n에 추가한다.

완료 기준: 플랫폼 수가 많아도 확인 버튼이 밀리지 않고, 비활성화 후 검색어와 카드를 유지한다.

## 작업 4 — 검증과 결과 작성

- [x] 공유 경로, 독립 링크·복사본, 같은 이름의 다른 경로를 다루는 기존 테스트에 회귀 사례를 추가한다.
- [x] 개별 제외 설정 보존, 재스캔 후 복원, 복원 충돌, 파일·DB 실패 복구를 검증한다.
- [x] 플랫폼 0개·1개·수십 개, 긴 이름, 키보드 조작, 취소, 중복 클릭을 검증한다.
- [x] 관련 Vitest·cargo test, 타입 검사, lint와 프로젝트 기준 Clippy를 실행한다. 기존 실패는 이번 변경의 실패와 구분한다.
- [ ] tauri-fast-verify 지침에 따라 임시 스킬·설정·DB를 이용해 개발 앱에서 전체 흐름을 검증한다. 사용자 실제 스킬은 토글하지 않는다.
- [x] 기존 platform-skill-control-design.md를 최종 구현에 맞게 수정한다.
- [x] 구현한 동작, 실제 검증 결과, 남은 제한을 한국어로 작성하고 체크리스트를 실제 결과에 따라 갱신한다.

완료 기준: 부모 에이전트가 변경을 검토하고 검증 증거를 확인한 뒤 완료로 보고한다.


## 실제 검증 결과

| 검증 | 결과 |
|---|---|
| `pnpm typecheck` | 통과 |
| `pnpm lint` | 통과, 경고 0개 |
| 변경 관련 Vitest 5개 파일 (`--maxWorkers=1`) | 127개 통과 |
| `cargo clippy --locked --offline -- -D warnings` | 통과 |
| `cargo test --locked --offline shared_ -- --test-threads=1` | 36개 통과 |
| `cargo test --locked --offline paused_observation_survives_rescan -- --test-threads=1` | 1개 통과 |
| 실제 public Rust API를 실행하는 일회성 스모크 | 임시 HOME·SQLite·파일·심볼릭 링크에서 모든 검사 통과 |
| 실제 브라우저의 공유 영향 다이얼로그 | 0·1·60개 플랫폼, 긴 이름, Enter로 펼치기, 취소 확인 |

Vitest 대상은 `skillUsageStore`, `SharedSkillImpactDialog`, `UnifiedSkillCard`, `UniversalInstallView`, `PlatformView`다. 처음 실패한 타입 지시문, mock 속성 정의, busy 상태 누수, DOM 구조에 종속된 검사와 중단 과정에서 잘린 테스트를 정리했다. 관련 범위의 최종 실패는 없다. 전체 프론트·전체 Rust 테스트는 실행하지 않았으며 기존 문서의 다른 실패가 해결됐다고 주장하지 않는다.

일회성 Rust 스모크는 확인 이후 범위 변경 거절, 공유 링크 끄기, 실제 재스캔 후 카드 유지, 원본·독립 링크·개별 제외 보존, 복원 위치 충돌 보호, 복원, Universal 전체 확인 목록, 개별 중지 항목의 일괄 복원 제외를 실행했다. 회귀 테스트는 파일 이동 실패 및 DB 쓰기 실패 롤백도 확인한다. 이 스모크 소스와 임시 데이터는 검증 후 제거했다.

60개 플랫폼의 실제 브라우저 측정: 펼친 목록 높이 240px, 내용 높이 1170px, 현재 플랫폼이 첫 항목. 확인 버튼 하단 703px로 900px viewport 안에 남았다. 이 확인은 실제 UI 컴포넌트와 시각화 전용 데이터로 수행했으며 네이티브 IPC 검증으로 계산하지 않는다.

### 남은 검증 제한

격리된 HOME으로 `tauri dev`를 빌드·실행했지만 자동화 가능한 네이티브 창을 얻지 못했다. System Events의 앱 창 목록이 비었고 화면 캡처는 검은 화면이었으며 WebView에서 받을 예정인 완료 보고가 시간 내 오지 않았다. 프로세스는 중지했다. 따라서 **실제 네이티브 화면에서 확인창 → 끄기 → 재스캔 → 복원을 이어서 조작한 전체 흐름은 미검증**이며 위 체크박스를 완료 처리하지 않는다. 실제 backend 파일/DB 흐름과 브라우저 UI 검증은 각각 통과했다.

사용자의 실제 스킬·설정·DB를 토글하지 않았다. 커밋·푸시·설치 앱 교체·배포 빌드는 하지 않았다. 기존 모델 강제 지정 요구는 적용하지 않았다.
