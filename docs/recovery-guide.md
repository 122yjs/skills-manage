# 백업과 복원 사용법

설정의 **백업 및 휴지통**에서 제거 전 보존한 파일과 DB 백업을 확인한다. 파일 백업과 휴지통 항목은 30일간 보관하며 DB 백업은 자동 만료하지 않는다.

## 스킬 파일 복원

1. 원래 위치와 만든 시각을 확인한다.
2. **파일 복원**을 누른다. 원래 위치에 파일이 있으면 덮어쓰지 않고 중단한다.
3. 복원이 끝나면 스킬 목록을 다시 스캔한다.

보관함에서 삭제한 스킬을 복원하면 원본 파일이 돌아온다. 이전 도구 적용과 컬렉션 소속을 모두 자동 복원하는 작업은 아니다. 필요한 도구에 다시 적용할 수 있다. 복사 설치 백업은 사용자가 추가하거나 수정한 파일을 포함하며, 원래 설치 위치로 복원하면 앱에서 관리할 수 있는 설치 기록도 복원한다.

**영구 삭제**는 복구 파일을 제거한다. 삭제하기 전에 항목을 다시 확인해야 한다.

## DB 백업

DB는 도구 목록 표시 설정, 컬렉션, 설치 기록 등 앱의 관리 정보를 저장한다. 스킬 파일 자체는 별도의 파일 백업 대상이다. DB 백업만으로 모든 스킬 파일을 복구할 수는 없다.

설정에서 **데이터베이스 백업 만들기**로 현재 상태를 보존할 수 있다. **위치 열기**로 백업 파일이 있는 폴더를 연다.

DB 전체를 복원해야 한다면 다음 순서를 따른다.

1. 복원하려는 DB 백업의 위치를 확인한 뒤 skills-manage를 완전히 종료한다. 개발용 앱도 실행 중이면 종료한다.
2. 현재 DB 폴더의 `db.sqlite`, `db.sqlite-wal`, `db.sqlite-shm` 중 존재하는 파일을 **모두 함께 별도 폴더로 옮겨 보존**한다. 기존 파일을 삭제하지 않는다. 기본 DB 폴더는 `~/.skillsmanage`다.
3. 선택한 백업 SQLite 파일을 원래 DB 폴더에 `db.sqlite`라는 이름으로 복사한다. 이전 WAL 파일을 새 DB와 섞지 않는다. WAL은 DB의 최근 변경 내용을 담는 보조 파일이다.
4. 앱을 실행하고 설정과 컬렉션을 확인한다. 스킬 파일은 현재 디스크 상태를 다시 읽으므로, 파일까지 과거 상태로 돌아가지는 않는다.

문제가 생기면 앱을 종료하고 복원 시도에 사용한 DB 파일들을 별도로 옮긴 다음, 2번에서 보존한 파일들을 한 묶음으로 되돌린다.
