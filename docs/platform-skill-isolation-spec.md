# 플랫폼별 스킬 선택과 중복 출처 정리 명세

상태: 요구사항 확정, T2 구현 진행 중. 기준: 8027712, 2026-09-21.
[결정](adr/0001-platform-skill-control-scope.md) · [60개 플랫폼 조사](research/platform-skill-capabilities-2026-09-21.md) · [구현 작업](platform-skill-isolation-tasks.md)

## 사용자가 얻을 결과

airbnb-full을 OpenClaw에서는 켜고 OMP에서는 끈다. 같은 조작을 등록된 모든 플랫폼에 제공하되, 실제 적용할 수 없는 상태는 이유와 남은 출처를 표시한다. 사용하는 플랫폼에는 내용이 같은 여러 출처 중 하나를 대표로 선택한다. 내용이 다르면 사용자가 선택한다.

공용 설치를 플랫폼별 설치로 바꾸는 기능도 포함한다. 원본 저장소와 다른 플랫폼의 사용 상태를 보존하고 되돌릴 수 있어야 한다. 새로 등록한 플랫폼에는 전환한 스킬을 자동 설치하지 않는다. 업데이트로 다른 사본과 달라져도 선택한 출처를 유지하고 다음 스캔에서 알린다.

외부 복사본 잔존은 허용한다. 적용 대상을 정확히 표시하고, 잔존 출처가 있으면 전체 스킬이 완전히 꺼졌다고 표시하지 않는다. 기존 대화의 내용을 지우거나 에이전트가 일반 파일 읽기로 같은 문서를 다시 여는 것까지 막는 기능은 아니다.

## 완료 여부를 구분하는 기준

| 관찰 | 말할 수 있는 결과 |
|---|---|
| 카드 하나로 묶음 | 목록 표시 정리 |
| 플랫폼 설정/설치 변경 후 다시 읽음 | 설정 적용 확인 |
| 새 세션의 실제 스킬 목록에서 제외/대표 하나 확인 | 해당 버전·범위에서 노출 제어 확인 |
| 본문 로딩 또는 모델 요청을 관찰 | 해당 시나리오의 중복 로딩 감소 확인 |

파일 개수나 토글 모양만으로 컨텍스트 절감을 주장하지 않는다. 설정 성공과 실행 중 세션 반영을 분리한다. 60개 중 일부만 검증되면 전체 플랫폼 지원 완료가 아니다.

## 플랫폼별로 확인할 능력

기존 platform_skill_control 모듈에서 플랫폼별 실제 처리 코드를 확장한다. 화면에 플랫폼 이름별 파일 수정 분기를 넣지 않는다. 별도 플러그인 프레임워크나 자체 스킬 실행기는 만들지 않는다.

각 플랫폼 구현은 다음 사실을 반환한다.

| 항목 | 의미 |
|---|---|
| 제품·버전·실행 종류 | 같은 회사의 IDE/CLI/SDK를 구분 |
| 읽는 경로와 조건 | 사용자·프로젝트·조상/하위·호환·플러그인·추가 경로·프로필 |
| 끄기 단위 | 정확한 출처 경로 / 이름 / 플러그인 / 전체 탐색 범위 |
| 실제 효과 | 모델 목록 제외, 자동 선택 제외, 수동 호출 제한을 구분 |
| 대표 선택 가능성 | 다른 출처만 제외하거나 우선순위를 안전하게 바꿀 수 있는지 |
| 반영 조건 | 즉시·명시적 재로드·새 대화·재시작·미확인 |
| 근거 | 공식 URL/고정 소스, 검증한 버전, 확인 범위 |

기존 supported 하나만으로 “독립 끄기”와 “대표 출처 선택”을 함께 판단하지 않는다. 예를 들어 이름 단위 off는 같은 이름을 모두 끌 수 있지만 특정 버전 하나만 남기는 기능은 아니다. 전체 Skills Tools나 기본 resource 상속을 끄는 기능도 스킬 하나를 끄는 대체재로 쓰지 않는다.

사용자 정의 플랫폼도 조사 대상에서 제외하지 않는다. 등록한 폴더라는 정보만으로 전용임을 가정하지 않고 실제 읽기 경로와 다른 플랫폼의 접근을 검증한 범위에서만 파일 기반 제어를 제공한다.

## 대상과 상태

안정적인 플랫폼 ID와 출처 경로를 사용한다. 스캔 때 바뀌는 행 번호나 표시 이름은 저장 키로 쓰지 않는다. 파일 경로는 별칭 경로와 실제 대상 경로를 모두 보존한다. 같은 원본을 가리키는 서로 다른 설치 링크는 각각 복원할 수 있어야 한다.

대표 선택은 플랫폼·작업 범위·스킬 묶음에 속한다. 묶음은 기존 출처들에 부여하는 안정적인 ID이며 이름이나 내용 해시로만 식별하지 않는다. 내용 해시는 업데이트 때 바뀌므로 영구 ID로 부적합하다. 프로젝트별 지침은 해당 프로젝트 범위를 유지한다. 전역 대표 선택으로 다른 프로젝트 지침을 덮지 않는다.

저장은 기존 platform_skill_controls의 원래 값/적용 값과 복원 계약을 유지한다. 대표 선택에는 플랫폼, 작업 범위, 묶음 ID, 선택한 안정적 출처, 마지막 비교 결과가 필요하다. 설치 전환에는 아래 작업 기록만 더한다. 거대한 범용 정책 DB는 만들지 않는다.

원하는 상태와 관측 결과를 분리한다.

| 상태 | 표시할 내용 |
|---|---|
| 적용 전 | 사용자가 원하는 켜기/끄기·대표 |
| 적용됨 | 확인된 설정 또는 설치 결과 |
| 반영 대기 | 설정은 저장했으나 세션 재시작 등이 필요 |
| 일부 출처 남음 | 지정 범위는 처리했지만 별도 출처 존재 |
| 외부 변경 | 앱이 마지막 적용한 값과 현재 값이 다름 |
| 확인 필요 | 버전·경로·권한·기능 근거 부족 |
| 복구 필요 | 일부 단계만 완료되어 재개/되돌리기가 필요 |

조회·스캔은 설정을 몰래 다시 쓰지 않는다. 외부 변경은 알리고 재적용 동작을 제공한다.

## 같은 내용의 대표 출처

1. 현재 플랫폼이 같은 작업 범위에서 읽을 수 있는 출처를 모은다. 앱이 찾은 모든 저장소를 한 세션의 후보로 섞지 않는다.
2. 기존 skill_duplicates의 실제 경로 및 전체 패키지 비교를 재사용한다. SKILL.md뿐 아니라 스크립트·참조 파일·실행 비트까지 같아야 한다. 내부 링크·오류·비교 한도 초과는 비교 불가다.
3. 내용이 같고 범위·권한·상대 경로 의미도 호환되면 대표 하나를 사용한다. 이미 선택한 출처가 있으면 유지한다. 없으면 현재 런타임이 사용하는 출처를 우선한다. 그것도 확인되지 않으면 안정적 경로 순서로 제안하되 적용 계획에서 보여준다.
4. 이름만 같고 내용이 다르거나 비교 불가이면 자동 선택·덮어쓰기하지 않는다. 경로, 출처, 변경 파일과 차이를 보여주고 사용자가 선택한다.
5. 선택 후 제외/설치 계획을 만들고 적용한다. 런타임이 원래 동명 하나만 고르며 그 출처가 이미 일치하면 불필요한 파일 이동을 하지 않는다.
6. 선택한 출처가 없어지면 확인 필요로 전환한다. 같은 이름의 다른 경로로 조용히 갈아타지 않는다.
7. 내용이 달라져도 대표 선택을 유지한다. 선택한 출처 자체의 정상 업데이트는 막지 않으며, 다른 복사본과의 차이를 다음 스캔에서 알린다.

파일 내용이 같아도 부모 디렉터리의 자료를 참조하거나 프로젝트 범위가 다르면 실행 의미가 달라질 수 있다. 바이트 비교 결과를 실행 동등성으로 확대하지 않는다.

## 적용 방식 선택

먼저 공식 개별 제외 설정을 사용한다. 원본을 옮기지 않아 다른 플랫폼에 대한 영향이 가장 작다. 상위 프로젝트/조직/에이전트 설정이 이를 덮는지 읽고 실제 효과를 계산한다. 사용자 설정만 썼다는 이유로 프로젝트에서도 제외됐다고 판정하지 않는다.

개별 제외가 없거나 특정 출처 선택에 부족하면 관리 설치를 분리하는 계획을 만든다. 계획에는 현재와 변경 후 각 플랫폼이 읽을 실제 경로를 포함한다. 전용 폴더라는 이름만으로 독립성을 가정하지 않는다.

예를 들어 Cursor를 끄고 Claude를 켜기 위해 공용 항목을 ~/.claude/skills로 옮기면 Cursor가 그 경로도 읽으므로 실패한 계획이다. 반면 꺼 둔 플랫폼이 읽지 않는 OpenClaw 경로만 필요하고 다른 사용처를 보존할 수 있다면 전환 후보가 된다. 이 판단은 [공식 경로 조사](research/platform-skill-capabilities-2026-09-21.md)를 실제 버전·설정에 대조한 뒤 수행한다.

실행 옵션이나 별도 프로필로만 가능하면 적용 범위가 그 실행에 한정됨을 표시한다. 사용자 요청 없이 셸 별칭·실행 래퍼·전역 HOME·플랫폼 기본 프로필을 바꾸지 않는다. 원격 서버/클라우드 복사본은 로컬 토글 성공에 포함하지 않는다.

현재 근거로 다른 플랫폼 보존과 제외를 동시에 만족시킬 방법이 없으면 제한 사유를 반환한다. 이는 아직 풀어야 할 플랫폼 지원 과제이며, 성공한 것처럼 DB만 바꾸는 이유가 되지 않는다.

## 공용 설치 전환 절차

전환은 실제 이동 대상을 검토하는 명시적 작업이다. 평소 토글이 공용 설치 전체를 몰래 끄지 않는다.

1. **계획:** 설치 항목, 원본 저장소/보관함, 원시 링크 대상, 켜 둘 플랫폼, 꺼 둘 플랫폼, 남는 별도 출처, 변경할 설정, 복원 위치를 계산한다. 읽기 경로가 겹치는 소비자까지 포함한다. 관측되지 않은 외부 도구는 보존 보장 범위 밖임을 확인창에 표시한다.
2. **준비:** 필요한 복구 공간·권한·파일시스템·대상 충돌을 검사한다. 원본 저장소/플러그인 소유 파일은 이동하지 않는다. 공용 항목이 링크면 링크만 다룬다. 일반 폴더면 관리 가능한 설치 사본인지 확인하고, 내용과 메타데이터를 보존한 복구 사본을 만든다. 원본과 설치를 구분할 수 없으면 중단한다.
3. **재확인:** 기존 shared_entry_key/영향 토큰을 재사용해 실행 직전 다시 계산한다. 설정·링크·출처·플랫폼 목록이 바뀌면 오래된 계획을 적용하지 않는다.
4. **기록:** 파일 변경 전에 작업 ID, 원래 값, 적용 예정 값, 백업/대상 경로, 현재 단계를 내구성 있게 저장한다. 설정 전체의 비밀 값을 로그나 사용자 보고에 노출하지 않는다.
5. **적용:** 새 관리 설치를 준비하고 검증한 뒤 기존 공용 설치 항목을 복구 가능한 위치로 옮긴다. 플랫폼별 설정은 지원되는 형식으로 필요한 키만 수정한다. 임시 준비 위치는 플랫폼이 읽는 루트 밖에 둔다.
6. **검증:** 켜 둔 플랫폼의 출처·보조 파일 접근을 확인한다. 꺼 둔 플랫폼의 대상 노출이 사라졌는지, 대표 출처가 일치하는지 확인한다. 재로드가 필요하면 반영 대기다. 재스캔 실패도 완전 성공으로 표시하지 않는다.
7. **완료/복구:** 관측과 DB를 갱신하고 기록을 완료한다. 실패하면 이번 작업의 변경만 역순 복원한다. 다른 프로세스가 바꾼 항목은 덮지 않고 충돌과 남은 복구 경로를 표시한다.

사용 중 프로세스의 파일 탐색과 여러 파일 변경을 하나의 원자적 동작으로 만들 수는 없다. 앱 내부 작업은 직렬화하되, 전환 도중에는 일시적 중복/누락 가능성과 새 세션 반영 조건을 표시한다. “다른 플랫폼 보존”은 최종 상태와 실패 복구의 계약이며 모든 실행 중 세션의 무중단 전환 약속은 아니다.

일반 폴더를 보관함으로 수용하는 경우 기존 skill_origins 메타데이터를 보존하고 새 출처로 임의 재해석하지 않는다. 링크와 복사 설치의 업데이트 방식은 기존 동작을 유지한다. 출처 분리가 업데이트 추적을 끊는다면 계획을 적용하지 않는다.

## 동시 변경과 설정 파일

usage_lock, control_lock, skill_origin의 mutation_lock과 recovery 잠금이 각각 존재한다. 전환용으로 잠긴 public 함수를 중첩 호출하지 않는다. 실제 호출 관계를 조사한 뒤 공통 진입 순서와 잠금 보유 상태의 내부 함수를 정하고, 업데이트·삭제·재스캔과 충돌하는 테스트를 둔다. 새 전환 잠금 하나를 추가하는 것만으로 다른 기존 쓰기를 막았다고 보지 않는다.

설정은 파싱·부분 변경·다시 읽기로 검증한다. TOML은 기존 toml_edit를 활용한다. JSONC/JSON5/YAML은 주석과 무관한 값 보존까지 검증된 편집 방법이 필요하다. 일반 JSON 파서로 읽고 전체 재출력하여 주석을 없애지 않는다. 형식을 모르면 쓰기를 거부한다. 설정 파일 자체가 링크이면 링크를 일반 파일로 바꾸지 않는다.

복원은 현재 값이 앱이 적용한 값인지 비교한 뒤 수행한다. 기존 사용자 차단이나 상위 범위 정책을 강제로 풀지 않는다. 앱이 추가한 정확한 항목만 제거하며 이름 glob·allowlist 규칙을 다른 스킬에 영향을 주도록 확대하지 않는다.

## 화면 계약

플랫폼 화면의 기본 토글은 “이 플랫폼에서 사용”을 뜻한다. 공용 설치 전체 제어는 영향 목록이 있는 별도 조작으로 둔다. 검색 결과·상세·플랫폼 카드가 동일한 backend 결과를 사용한다.

중복 출처를 접어 보여주더라도 “대표 출처”, “다른 내용”, “비교 불가”, “별도 출처 남음”을 구분한다. 설정 적용, 반영 대기, 확인 필요는 별도 상태로 보여준다. 기술적인 adapter 이름이나 설정 파일 문법은 상세 정보에만 둔다.

플랫폼을 새로 발견하거나 스캔 순서가 바뀌어도 전환한 스킬을 자동 설치하지 않는다. 이미 외부에서 노출된 스킬은 발견 상태로 표시한다. 외부 노출을 앱이 설치한 것으로 기록하거나 자동 제거하지 않는다.

## 검증 계약

모든 자동 검증은 임시 HOME/설정/프로젝트/DB에서 수행한다. 실제 설치본 검증은 합성 스킬과 플랫폼 목록/로더 인터페이스를 우선 사용한다. 모델 API 호출 없이 검사할 수 있는 범위부터 확인한다. 실사용 스킬과 인증 설정을 시험용으로 바꾸지 않는다.

필수 시나리오:

- 공용 airbnb-full: OpenClaw 켜짐, OMP 꺼짐, 원본과 제3 플랫폼 유지, 재시작 후 동일.
- Cursor가 Claude 경로를 함께 읽는 반례: 잘못된 전환 계획을 실행 전에 거절.
- 동일 파일의 링크 2개, 별도 동일 복사본, 같은 본문/다른 보조 파일, 다른 실행 비트, 내부 링크, 비교 한도 초과.
- 같은 이름의 다른 버전 선택, 프로젝트 범위 유지, 우선순위와 실제 대표 일치.
- 업데이트 후 대표 유지, 대표 삭제/이동, 새 플랫폼 추가, 외부 설치 재등장.
- 설정 우선순위, 기존 glob/allowlist, CodeBuddy plugin 예외, AGY 명시 등록 제외와 자동 발견의 구분, OpenClaw skillKey, Codex 경로 표기.
- 단계별 실패·프로세스 종료 후 복구, 적용 도중 외부 설정 변경, 복원 위치 충돌, 깨진 링크·권한·읽기 전용.
- 기존 개별/일괄 비활성 복원 및 공용 설치 전체 조작 회귀.
- UI 토글 의미·검색어 유지·미확인 표시·중복 클릭 방지·재조회 실패 처리.

60개 플랫폼 각각에서 버전과 위 계약에 해당하는 실행 증거를 기록한다. 확인 불가 행은 계속 미완료다. 문서만 채웠거나 몇 개 adapter가 통과한 결과를 “모든 플랫폼 완료”로 보고하지 않는다.
