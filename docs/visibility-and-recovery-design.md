# 도구 표시와 스킬 적용, 복구 설계

## 동작 기준

- 기존 agents.is_enabled 저장값과 IPC는 호환성을 위해 유지하되 의미는 도구 목록 표시로 한정한다. 숨긴 도구도 스캔하고 설치 관리에서 확인할 수 있다. 표시 변경은 스캔이나 파일 변경을 실행하지 않는다.
- 전체 표시 / 전체 숨기기는 관리 가능한 플랫폼에만 적용한다. 보관함, 공용 설치, Obsidian 같은 고정 항목은 제외한다.
- 적용 해제는 선택한 설치 위치만 제거한다. 공용 설치와 플러그인의 읽기 전용 출처는 별도로 표시한다.

## 파일 복구

- 관리 중인 복사 설치를 해제하기 전에 전체 복사본을 보존한다. 변경 여부 판별에 의존하지 않아 사용자가 추가한 파일도 잃지 않는다.
- 보관함 스킬 또는 묶음 삭제 전에 전체 파일을 휴지통에 보존한다. 백업 생성에 실패하면 삭제를 중단한다.
- 복구 데이터는 DB와 같은 폴더 아래 recovery에 저장한다. 실제 파일, 생성 시각, 원래 경로, 종류, 복구에 필요한 설치 정보를 항목별로 기록한다. 임시 항목을 완성한 후 공개한다.
- 파일 항목은 30일 보관 후 정리한다. 복원과 영구 삭제는 설정의 백업 및 휴지통에서 수행한다.
- 복원은 원래 경로가 비어 있을 때만 허용하며, 경로 중간의 심볼릭 링크를 통한 다른 위치 쓰기를 차단한다. 실패한 복원은 백업을 남긴다.
- 보관함 복원은 원본 파일을 되살린다. 이전 플랫폼 적용을 자동으로 다시 켜지 않는다. 스캔으로 목록을 갱신한다. 모음 등 과거 DB 정보는 별도 DB 백업에 보존된다.
- 복사 설치본을 원래 위치로 복원하면 설치 기록도 복원하여 이후 적용 해제가 가능해야 한다.

## 데이터베이스 백업

- SQLite의 일관된 스냅샷 기능을 이용해 기록되지 않은 WAL 변경도 포함한다. 실행 중인 db.sqlite 파일만 단순 복사하지 않는다.
- 기존 DB 초기화 전, 보관함 삭제 및 위치 이동 전에 스냅샷을 만든다. 새 빈 DB와 메모리 테스트 DB는 실제 사용자 폴더를 건드리지 않는다.
- 설정에서 수동 DB 백업과 백업 위치 열기를 제공한다. DB 전체 복원은 앱을 종료한 상태에서 진행하는 수동 작업으로 명시한다.
- DB 백업은 파일 휴지통과 구분하여 자동 만료하지 않는다.

## UI와 IPC 계약

설정에 백업 및 휴지통을 추가한다. 목록 항목은 id, kind(copy_backup / vault_trash / database), label, original_path, created_at, expires_at(없으면 null), backup_path를 포함한다.

- list_recovery_entries() -> RecoveryEntry[]
- restore_recovery_entry({ id }) -> void: 파일 항목만 복원한다.
- delete_recovery_entry({ id }) -> void: 확인 후 영구 삭제한다.
- create_database_backup() -> RecoveryEntry: 수동 DB 백업이다.

파일 복원 후 스캔과 보관함 목록을 갱신한다. 영구 삭제는 항목별 확인을 거친다. 모든 문구는 한국어, 영어, 중국어 번역 키를 사용한다.

## 검증

숨김 이후에도 스캔 결과와 설치 상태가 유지되는지, 표시 변경에 스캔 호출이 없는지 확인한다. 파일 복구는 임시 디렉터리에서 수정된 복사본 보존, 원본 삭제와 복원, 충돌 거절, 백업 실패 시 원본 유지, 경로 및 심볼릭 링크 검증, 만료 정리를 확인한다. DB 백업은 생성된 SQLite를 다시 열어 내용을 검증한다.
