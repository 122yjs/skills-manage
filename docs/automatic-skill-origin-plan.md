# 수동 설치 스킬의 출처 자동 인식 계획

상태: 2026-09-28 작성한 계획(당시 코드 기준 `4c63aeb`). 자동 출처 연결과 안전한 업데이트는 일부 구현했으며, 아래 나머지 항목은 향후 검토 대상이다.

## 1. 목표와 확정된 요구

앱이 이미 찾은 스킬을 대상으로 사용자가 저장소 URL을 입력하지 않아도 GitHub 출처를 찾는다. 근거가 충분하면 출처를 연결하고 기존 스킬셋 화면에 자동으로 묶는다. Hermes의 수동 복사본뿐 아니라 다른 플랫폼의 복사본과 바로가기에도 같은 판별 규칙을 적용한다.

사용자는 **수정본도 복수 근거가 맞으면 자동 연결**하는 방식을 선택했다. 자동 연결은 앱 DB에 출처를 기록하는 작업이다. 스킬 파일, 실행 권한, 설치 위치를 바꾸거나 원본 업데이트를 적용하지 않는다.

출처와 버전을 구분한다. 출처가 추론되어도 정확히 같은 버전을 확인하지 못하면 기존 `baseline_state=unknown`을 유지한다. 추론을 전체 파일 검증으로 표시하지 않는다.

## 2. 현재 확인한 사실

- `installation_records.rs`는 공용 `.agents/.skill-lock.json` 및 프로젝트 `skills-lock.json`을 읽는다. Hermes `.hub/lock.json`이나 일반 복사본의 문서 단서는 읽지 않는다.
- `recorded_origins_for_target()`은 다른 설치본의 출처를 가져올 때 전체 파일 일치를 요구한다. 이 보호 장치는 유지하고, 수정본 판단은 별도 근거를 갖춘 경로로 추가한다.
- `discover_skill_origin_impl()`은 설치 기록을 자동 연결하고, 공개 검색 결과는 후보로만 제공한다. 공개 검색의 `content_match`는 `SKILL.md`만 비교하므로 전체 스킬 일치를 뜻하지 않는다.
- `discover_installed_origins()`는 보관함과 관리 설치를 대상으로 실행된다. 순수 읽기 전용 관찰 항목은 빠진다.
- `RemoteCache`, 커밋에 고정된 저장소 다운로드, 파일 목록·내용 해시·실행 권한 비교, `skill_origins`, `skill_origin_ignores`, 저장소별 묶음은 이미 있다.
- `AppShell`은 시작·재스캔·6시간 간격으로 출처를 확인한다. 백그라운드 연결 후 중앙 목록은 갱신하지만, 이미 열린 모음집은 별도 갱신이 필요하다.
- 로컬 조사 대상은 Hermes `korean` 폴더의 58개와 루트의 `k-skill-setup`, `zipcode-search`를 합한 60개다. **60개 모두 k-skill 출처라는 뜻은 아니다.**
- 이 60개 중 `SKILL.md`에 GitHub 링크가 있는 항목은 13개이고, `NomaDamas/k-skill` 링크는 `k-skill-setup`에서 확인했다. 다른 링크는 스킬이 이용하는 별도 도구의 저장소일 수 있다.
- 현재 GitHub의 `korea-weather/SKILL.md`는 짧은 CLI 안내문이고 로컬 파일은 긴 사용 설명이다. 최신 `SKILL.md` 하나만 비교하면 구버전 인식을 놓친다.

## 3. 판별 규칙

### 공통 원칙

후보 발견, 출처 연결, 파일 업데이트를 구분한다. 이름·설명·폴더 이름만으로 연결하지 않는다. 여러 단서가 같은 문서의 동일 링크를 반복한 것이라면 하나의 근거로 센다. 서로 다른 출처 기록이나 동등한 후보가 충돌하면 자동 연결하지 않는다.

결과는 `연결됨`, `복수 근거로 자동 연결`, `후보 확인 필요`, `단서 없음`, `조회 보류`로 구분한다. 기존 연결의 상태와 새 발견 결과를 혼동하지 않는다.

### A. 설치 기록 또는 Git으로 경로가 확인되는 경우

- 실제 설치 경로에 대응하는 설치 기록이 저장소와 스킬 경로를 특정하면 자동 연결한다.
- Git 저장소 안의 설치본은 Git 원격 URL, 저장소 내부 상대 경로, 추적 중인 `SKILL.md`를 함께 확인한다. 상위 프로젝트에 Git이 있다는 사실만으로 그 프로젝트를 스킬 출처로 삼지 않는다.
- 복수 원격 URL이 충돌하거나 추적되지 않은 파일이면 후보로 남긴다.
- 전체 파일이 확인한 커밋과 같으면 그 커밋과의 일치를 기록한다. 다르면 출처만 연결하고 버전은 `unknown`으로 둔다.

### B. 설치 기록 없는 일반 복사본

로컬에서 발견한 GitHub 단서와 원격의 실제 스킬 경로가 일치하고, 전체 파일 목록·내용·지원되는 실행 권한까지 같으면 자동 연결한다. 알려진 후보 안에서 출처가 하나여야 한다. GitHub 전체를 검색해 유일성을 증명했다고 표시하지 않는다.

### C. 일부 수정된 복사본

다음 세 종류의 근거를 모두 요구한다. 가중치 점수나 AI 판단은 도입하지 않는다.

1. **저장소 근거:** 해당 스킬의 출처 메타데이터, 설치 안내문의 저장소 링크, 또는 근거가 확인된 다른 설치본이 후보 저장소를 가리킨다. 같은 폴더에 있다는 사실만으로는 부족하다.
2. **스킬 식별 근거:** 그 저장소 안에서 스킬 이름과 설명 또는 명시된 원본 경로가 하나의 스킬을 가리킨다. 이름과 설명은 합쳐서 한 종류의 근거로 취급한다.
3. **내용 근거:** 수정되지 않은 의미 있는 파일이나 본문 구간이 그 원본과 일치한다. 단순 링크·이름·설명은 여기에서 다시 세지 않는다.

내용 근거의 첫 구현 기준은 아래처럼 고정한다. 검증 결과 없이 조건을 완화하지 않는다.

- `SKILL.md` 본문, `scripts/`, `references/`, 또는 스킬이 명시적으로 참조하는 같은 저장소 안의 본문 파일을 비교한다. 현재처럼 본문이 `instruction.md`로 옮겨진 형식도 명시된 참조를 따라 읽기만 한다.
- 내용 파일 전체가 일치하면 최소 256바이트 이상이어야 한다. 같은 저장소의 여러 스킬에 공통으로 들어 있는 파일은 근거에서 제외한다.
- 단일 문서 수정본은 서로 다른 본문 문단 두 개 이상, 합계 400자 이상이 일치해야 한다. 줄바꿈과 연속 공백만 정규화한다. 제목·설명·라이선스·공통 설치/안전 안내·생성된 CLI 안내문은 제외한다.
- 문단 비교에서는 대상 원본 문서와 로컬 문서 각각의 비교 가능한 본문 중 일치 분량이 50% 이상이어야 한다. 짧은 공통 문구 두 개로 큰 문서 전체를 같은 출처로 오인하는 것을 막는다.
- 내용 근거가 경쟁하는 다른 저장소/스킬에도 똑같이 맞으면 자동 확정하지 않는다. 포크 관계나 별 개수로 승자를 고르지 않는다.

조건이 맞으면 출처는 `복수 근거로 자동 연결`, 버전은 `unknown`으로 저장한다. 무엇을 근거로 연결했는지 화면에서 볼 수 있어야 한다. 모든 내용이 바뀌어 검증 근거가 남지 않은 수정본까지 자동 연결하는 것은 목표가 아니다.

### D. 연결 금지 및 기존 선택 존중

- 이름만 같음, 설명만 같음, 같은 폴더에 있음, 외부 도구 링크만 있음, 공통 라이선스/안내문만 일치함: 후보까지만 허용한다.
- 기존 수동 연결은 자동으로 교체하지 않는다. `skill_origin_ignores`에 있는 경로는 재연결하지 않는다.
- 새 근거가 기존 추론과 충돌하면 재검토 상태를 표시하고 자동 재지정하지 않는다. 충돌이 풀리기 전 업데이트도 차단한다.

## 4. 후보 수집과 실행 흐름

1. 기존 스캔 결과에서 물리 경로별로 대상을 모은다. 바로가기는 실제 대상을 한 번만 판별하되, 설치 기록은 바로가기가 놓인 원래 경로에서도 읽는다.
2. 현재 지원하는 설치 기록, Hermes의 경로 지정 설치 기록, Git 추적 정보, 스킬의 출처 메타데이터와 GitHub 링크를 읽는다. Hermes 기록이 없다는 이유로 탐색을 끝내지 않는다.
3. 한 번의 실행에서 발견한 저장소 후보를 공유한다. `k-skill-setup`의 링크로 찾은 저장소의 전체 스킬 목록을 다른 설치본과도 대조한다. **후보만 공유하고, 연결 근거는 스킬마다 다시 확인한다.**
4. 원격 스킬 목록과 현재 내용을 저장소별로 한 번 내려받는다. 같은 이름뿐 아니라 정확한 내용 일치도 비교하여 폴더 이름만 바뀐 복사본을 찾는다.
5. 최신본과 구조가 다른 경우, 먼저 명시된 본문 참조와 로컬에 이미 있는 Git 이력을 확인한다. 그래도 부족하면 후보 스킬 경로의 최근 변경 이력을 제한적으로 조회한다.
6. A/B/C 규칙으로 판정하고, 연결 전 로컬 파일과 ignore/기존 연결 상태가 바뀌지 않았는지 다시 확인한다. DB 저장 후 목록·상세·모음집을 함께 갱신한다.

GitHub 전체를 대상으로 모든 스킬 이름을 무제한 검색하지 않는다. 첫 버전의 백그라운드 탐색은 로컬 단서와 이미 있는 카탈로그가 가리키는 저장소로 제한한다. 기존 상세 화면의 공개 검색은 유지하되, 결과를 자동 출처 증명으로 승격하지 않는다. 출처 흔적이 전혀 없는 설치본은 `단서 없음`으로 남을 수 있다.

## 5. 재사용할 구조와 최소 변경

- `src-tauri/src/commands/skill_origin/installation_records.rs`: 기존 형식 보존. 실제 경로를 검증하는 Hermes 기록 해석을 추가한다. 문서 링크를 신뢰할 수 있는 설치 기록으로 취급하지 않는다.
- 새 파일 `src-tauri/src/commands/skill_origin/discovery.rs`: 단서 수집과 A/B/C 판정의 작은 순수 함수들을 둔다. 어댑터 프레임워크나 플러그인 레지스트리는 만들지 않는다.
- `src-tauri/src/commands/skill_origin.rs`: 전체 탐색, 기존 `RemoteCache`, manifest 비교와 연결 저장을 재사용한다. 상세 조회와 백그라운드 작업이 같은 판정 함수를 쓴다.
- `src-tauri/src/commands/github_import.rs`: 기존 GitHub 인증·다운로드·경로 검증을 재사용한다. 자동 탐색에서 사용할 다운로드 크기 제한과 요청 중단 처리가 부족한 부분만 보완한다.
- `src-tauri/src/db.rs`: 발견 결과용 작은 테이블 하나를 추가한다. `target_key`, 입력 지문, 규칙 버전, 상태, 후보/근거 JSON, 확인 시각, 재시도 시각을 저장한다. 확정 연결은 기존 `skill_origins`, 해제 의사는 기존 `skill_origin_ignores`가 계속 담당한다.
- 입력 지문에는 스킬 파일뿐 아니라 실제 판정에 사용한 설치 기록/단서의 변경도 포함한다. 형제 스킬의 안내문 변경으로 새 저장소가 발견된 경우도 재평가한다.
- `AppShell.tsx`, `skillOriginStore.ts`, `SkillDetailView.tsx`와 기존 번역 파일: 자동 탐색 결과, 연결 근거, 확인 대기/오류, 재시도·연결 해제를 기존 화면에 추가한다. 신규 전용 화면은 만들지 않는다.
- `skill_groups.rs`의 저장소별 묶음 규칙을 재사용한다. 출처 자동 연결만으로는 단일 스킬의 여러 복사본을 스킬셋으로 만들지 않는다. 추론 여부는 구성원 단위로 표시한다.

읽기 전용 설치본은 **출처 표시와 묶음에 필요한 DB 기록만** 허용하도록 분리한다. `can_update`는 기존 관리 가능 여부에서 계산한다. 자동 인식 성공이 파일 수정 권한을 부여해서는 안 된다. 관찰 항목도 물리 경로로 합쳐 처리하며, 상세 화면의 읽기 전용 분기와 업데이트 명령 양쪽을 검증한다.

## 6. 비용·실패·데이터 보호

- 기존 시작/재스캔/6시간 확인 흐름에 붙인다. 새 상시 프로세스나 타이머는 만들지 않는다. 백그라운드 작업 중에도 앱 화면은 사용할 수 있어야 한다.
- 백엔드에서 전체 탐색의 중복 실행을 막는다. 네트워크 대기 중에는 기존 파일 변경 잠금을 잡고 있지 않는다.
- 첫 구현의 제안 한도: 한 실행당 신규 저장소 10개, 원격 동시 요청 2개, 탐색 시간 60초. 남은 대상은 실패가 아닌 보류로 기록하고 다음 실행에서 먼저 처리한다.
- 실패 응답도 실행 중 캐시에 넣어 같은 저장소의 오류를 스킬 수만큼 반복하지 않는다. 변경 없는 미확정 결과는 24시간 재사용한다. 로컬 단서 변경과 명시적 재시도는 캐시를 무효화한다.
- 원격 이력 조회는 현재 내용으로 판별하지 못한 유력 후보에만 사용한다. 스킬 경로의 최근 변경 최대 20건에서 커밋 후보를 찾고, 과거 스냅샷은 저장소당 최대 3개만 비교한다. 확인한 범위를 근거에 기록하고, 실패를 ‘출처가 다름’으로 해석하지 않는다.
- GitHub `403/429`는 응답 헤더의 재시도 시각을 따른다. 인증 실패, 삭제된 저장소, 네트워크 실패는 `조회 보류`로 남기고 기존 연결을 지우지 않는다.
- 자동 탐색용 저장소 다운로드는 압축 64MiB, 압축 해제 합계 256MiB, 파일 20,000개로 제한한다. 스트림을 읽는 도중과 압축을 푸는 도중에 검사한다. 제한을 넘으면 그 저장소만 보류한다.
- 로컬 수집은 앱에 등록된 설치 경로와 확인된 Git 루트 안에서만 한다. 홈 전체를 탐색하지 않는다. Git 명령은 인자 배열로 실행하며 셸·훅·네트워크 fetch를 호출하지 않는다.
- 문서의 명령, `npx`, 설치 스크립트는 실행하지 않는다. GitHub URL은 정규화·허용 호스트·상대 경로 검증을 통과한 값만 요청한다. 임의 URL 및 로컬 밖으로 나가는 참조를 따라가지 않는다.
- 파일 본문·로컬 경로·시크릿을 외부 AI나 검색 서비스에 업로드하지 않는다. GitHub에서 파일을 받아 비교는 로컬에서 수행한다.
- 출처 식별용 정규화/부분 비교는 기존 전체 manifest와 업데이트 안전 검증을 대체하지 않는다. 해시만 맞고 실행 권한이 다른 항목을 같은 버전으로 기록하지 않는다.

## 7. 구현 순서와 완료 조건

각 단계는 이전 단계의 결과를 사용한다. 하나의 기능을 끝까지 통과시키는 순서이며, 병렬 구현을 위해 임의로 나누지 않는다.

### 1단계: 일반 복사본 하나를 자동 연결

- [ ] 임시 설치 디렉터리와 메모리 DB를 사용하는 실패 테스트를 먼저 만든다.
- [ ] 대상 열거, 단서 수집, 공유 후보 저장소, 전체 일치 판정을 기존 연결 함수에 연결한다.
- [ ] 하나의 문서에서 얻은 URL로 다른 설치본을 발견해도 각 설치본의 파일을 독립적으로 검증한다.
- [ ] 저장소 이름이나 스킬 이름을 하드코딩하지 않는다.

완료: URL 수동 입력 없이 일반 복사본 두 개가 하나의 저장소 스킬셋으로 묶이고, 설치 파일은 전후 동일하다.

### 2단계: 수정본·구버전·충돌 처리

- [ ] C 규칙의 세 종류 근거와 내용 비교 기준을 순수 함수로 구현한다.
- [ ] `SKILL.md`에서 별도 본문으로 옮겨진 구조, 제한된 이력 조회, 폴더 이름 변경을 다룬다.
- [ ] 추론 근거를 저장하고 버전은 `unknown`으로 둔다.
- [ ] 이름·외부 도구 링크·공통 문구만 같은 반례, 포크 충돌, 사용자가 해제한 출처를 연결하지 않는다.

완료: 수정된 설치본은 복수 근거가 있을 때 자동 연결된다. 기존의 ‘내용이 다른 독립 복사본에 기록을 무조건 빌려주지 않는다’ 테스트도 그대로 통과한다.

### 3단계: 모든 설치 위치와 읽기 전용 표시

- [ ] Hermes `.hub/lock.json`, Git 추적 정보, 관리 설치와 관찰 항목을 같은 대상 흐름에 연결한다.
- [ ] 바로가기 여러 개는 물리 대상 하나로 처리하고 독립 복사본은 따로 판단한다.
- [ ] 읽기 전용 항목은 출처 표시만 허용한다. 업데이트 권한은 확대하지 않는다.

완료: 특정 플랫폼명에 의존하지 않는 테스트에서 동일하게 작동하고, 읽기 전용 설치본의 업데이트는 계속 거절된다.

### 4단계: 자동 실행·화면·재시도

- [ ] 발견 결과 캐시, 중복 실행 방지, 요청 한도, 보류와 재시도를 연결한다.
- [ ] 백그라운드 연결 완료 뒤 열린 모음집까지 새로 읽는다.
- [ ] 기존 상세 화면에 연결 근거와 버전 미확인을 표시한다. 후보/단서 없음/조회 실패도 구분한다.
- [ ] ‘연결 해제’ 후 다음 스캔에서 자동 재연결되지 않음을 확인한다.

완료: 재시작·재스캔·열린 모음집에서 결과가 일관된다. GitHub 오류가 있어도 앱 초기 목록을 막지 않는다.

### 5단계: 실제 k-skill 설치본으로 검증

- [ ] SQLite 백업 API로 일관된 임시 DB를 만든다. 실행 중인 DB 파일만 단순 복사하지 않는다.
- [ ] 기존 `live_recorded_origins_verify_against_github_in_database_copy` 방식을 확장해 Hermes 및 일반 발견도 검증한다.
- [ ] 실제 설치 파일은 읽기만 하고 연결 결과는 임시 DB에 기록한다.
- [ ] 조사 대상 60개 각각을 전체 일치/복수 근거/확인 대기/단서 없음/조회 보류로 보고한다. 별도 추가 스킬이 섞여 있으면 k-skill에 연결하지 않는다.
- [ ] 원격 커밋, 사용한 근거, 자동 연결 수, 원격 다운로드 횟수, 실행 시간, 파일 해시 전후 결과를 남긴다.

완료: 근거가 맞는 수정본의 실제 자동 연결을 확인하고, 잘못 묶인 반례는 0개이며, 원본 파일과 실제 앱 DB는 검증 과정에서 바뀌지 않는다. 실제 60개를 모두 자동 연결했다고 미리 약속하지 않는다.

## 8. 검증 범위

기존 Rust 테스트와 Vitest를 재사용한다. 새 테스트 프레임워크나 실제 네트워크에 의존하는 일반 테스트는 추가하지 않는다.

필수 회귀 사례: 전체 일치, 수정본의 복수 근거, 단일 문서 수정본, 본문 이동, 이름 변경, 중첩 설치, 외부 도구 링크 오인, 템플릿/포크 충돌, 실행 권한 차이, 오래된 기록, 파일 삭제/변경 경쟁, 해제 중 재탐색, 읽기 전용 업데이트 거절, 경로 탈출/위조 호스트, 오프라인/제한 응답, 실패 캐시, 저장소 중복 다운로드, 모음집 갱신.

변경 후 필요한 명령:

```bash
cargo test --manifest-path src-tauri/Cargo.toml skill_origin
cargo test --manifest-path src-tauri/Cargo.toml skill_groups
# github_import와 DB 변경에 해당하는 필터 테스트도 실행한다.
pnpm exec vitest run src/test/skillOriginStore.test.ts src/test/SkillDetailView.test.tsx src/test/SkillGroups.test.tsx src/test/AppShell.test.tsx
pnpm typecheck
pnpm lint
git diff --check
```

실제 앱에서는 개발 빌드로 시작 후 자동 발견, 수정본 표시, 모음집 갱신, 연결 해제 유지 네 가지를 확인한다. 계획 작성 단계에서는 위 구현 테스트와 빌드를 실행하지 않는다.

## 9. 이번 범위에서 제외

새 의존성, AI 출처 판정, 전체 GitHub 인덱스, 무제한 과거 커밋 검색, k-skill 전용 예외, 자동 재설치/업데이트, 폴더 이동, GitHub 이슈·PR 생성은 제외한다. 별도 설정 마법사와 작업 추적 체계도 만들지 않는다. ask-matt의 범위 정리와 문서화 흐름을 적용하되 기존 `CONTEXT.md`와 `docs/`를 사용한다.
